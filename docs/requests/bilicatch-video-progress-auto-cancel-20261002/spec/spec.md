# 规格：双轨下载进度单调化

## 模块标识与范围

- 请求：`bilicatch-video-progress-auto-cancel-20261002`
- 模块：视频下载进度聚合
- 范围：`download_percent` 的单调百分比规则，以及视频双轨进度回归保护

## 背景与目标

视频与音频下载会分别发现各自的总字节数。视频先上报时，百分比按视频总量计算；音频首次上报后，聚合总量突然增大，原始百分比可能低于已展示值。任务管理器按既有规则拒绝回退快照，进度回调再把拒绝映射为取消，导致用户未操作时任务被取消。

目标是让进度计算在总量扩展时保持单调，同时保留任务管理器对真正回退、非法快照和过期执行尝试的拒绝能力。

## 范围内事项

- 将 `download_percent` 的有总量分支钳制为不低于 `current.min(90)`。
- 增加覆盖真实复现数值的计算级回归测试。
- 增加覆盖“视频先上报、音频后加入、下载控制器不被取消”的行为级测试。

## 范围外事项

- 不修改用户取消、暂停、重试或任务状态机规则。
- 不修改媒体下载、断点续传、URL 刷新或 ffmpeg 合并流程。
- 不修改前端展示、IPC 契约、任务数据模型或持久化 schema。
- 不引入并发下载分片或新的进度平滑算法。

## 触发与启动条件

`VideoProgressSink::report` 收到某条媒体轨的 `DownloadProgress`，并将视频与音频进度聚合后调用 `download_percent`。

## 需求拆分摘要

单一非结构型缺陷：修正共享下载百分比计算的单调性，并用双轨行为测试防止合法总量扩展再次触发内部取消。

## 请求与工作流流程

1. 视频轨先上报 `1,014,439 / 1,514,175`，折算百分比为 60。
2. 音频轨首次上报后，聚合总量扩展为视频与音频总量之和。
3. 新原始比例低于 60 时，`download_percent` 返回 60，而不是回退值。
4. 任务管理器接受字节数增加且百分比不回退的快照。
5. reporter 返回 `true`，下载控制器保持 `Running`。
6. 后续聚合原始比例超过 60 后，展示百分比继续增长，下载完成后由既有流程进入处理与完成状态。

## 服务与模块设计

- `services::download::transfer` 继续拥有下载阶段百分比规则。
- `services::video::progress` 继续负责双轨聚合和上报，不复制单调化规则。
- `services::tasks::mutations` 保持严格校验，不为本缺陷放宽不变量。

## function-complete 行为拆解

- 当 `total` 缺失或为 0 时，返回 `current.min(90)`。
- 当 `total` 有效且计算比例高于当前值时，返回计算比例，最高为 90。
- 当 `total` 有效但计算比例低于当前值时，返回 `current.min(90)`。
- 当双轨总量首次扩展导致原始比例回退时，reporter 收到的百分比不得回退。
- 当 reporter 因真正的过期 attempt 返回 `false` 时，现有取消控制逻辑仍生效。

## 设计约束

- 单调规则只在共享纯函数内定义一次。
- 保留 90% 下载阶段上限，100% 仍由完成状态写入。
- 不在任务管理器内区分“合法回退”和“非法回退”，避免削弱状态机边界。

## 变更轴与模式决策

变化仅是稳定的局部数学规则，不存在 provider、版本或策略切换轴。采用直接代码，不引入命名设计模式或新层级。

## 代码上下文与影响假设

`download_percent` 当前已接收 `current` 参数，但仅在总量缺失时使用。本次补全该参数在有效总量分支中的单调保护，符合现有调用者意图。音频单轨调用者也会获得相同的单调保护，不改变正常递增场景。

## 接口与数据契约

- 外部接口：无变更。
- 内部函数：签名保持 `download_percent(downloaded: u64, total: Option<u64>, current: u8) -> u8`。
- 任务事件：`ExecutionUpdate::Progress` 字段与序列化形态不变。
- 错误与取消：reporter 的 `Ok(false)` 语义不变，仍表示当前更新未被活动 attempt 接受。

## 基础设施依赖策略

不涉及 MySQL、Redis、Kafka、gRPC、Kubernetes 或新增外部依赖。

## 安全与滥用防控

- 鉴权、授权：不适用。
- secret 与敏感数据：不适用；测试使用字节数，不固化媒体签名 URL 或凭证。
- 滥用面：不新增网络请求、文件访问或用户输入处理。

## rollout、迁移与回滚策略

- 无数据迁移。
- 随下一桌面版本发布即可生效。
- 回滚为恢复 `download_percent` 原实现；任务 schema 与已有数据完全兼容。

## 边界情况

- `total=None` 或 `Some(0)`：保持当前值，最高 90。
- `downloaded > total`：保持既有饱和到 90 的行为。
- `current > 90`：钳制为 90。
- 聚合总量增加：百分比不回退。
- 字节数真正回退：任务管理器仍拒绝快照，执行尝试仍停止。

## 验收标准

- AC-1：`download_percent(1_014_439, Some(3_124_379), 60) == 60`。
- AC-2：既有 50/100、100/100、超量、未知总量和零总量用例继续通过。
- AC-3：视频先达到 60%，音频首次上报使总量扩展时，真实 `DownloadControl` 状态保持 `Running`。
- AC-4：双轨 reporter 接收的 `percent` 序列不下降，且聚合 `bytes_downloaded`、`total_bytes` 使用两条轨道之和。
- AC-5：Rust 定向测试与完整测试均通过，格式检查无差异。

## 人工评审与交接

重点评审共享函数是否仅补全单调不变量、测试是否能在旧实现上稳定失败，以及任务管理器拒绝语义是否未被削弱。

## 风险

当总量显著扩展时，界面可能暂时停留在当前百分比，直到真实聚合比例追上；这是单调进度的预期表现，优于回退或错误取消。
