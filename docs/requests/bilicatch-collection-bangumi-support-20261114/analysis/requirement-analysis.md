# 需求分析：合集与番剧支持

## 分析摘要

本请求把 B 站两类“多视频单元”纳入既有下载链路：合集（UGC `ugc_season`，每个成员是独立稿件）与番剧（PGC `ep_id`/`season_id`）。当前实现只认 UGC 稿件的 `pages`（分 P），且输入层只接受 BV/av，因此合集内链接只能得到当前一条视频，番剧链接在输入校验即失败（C1–C4、C6–C8）。

2026-11-14 已由用户确认四项产品口径（H1–H4）：番剧只支持匿名可见的免费/限免集；合集与番剧共用统一选集列表；批量沿用多选手动勾选；选择粒度展开到分 P。据此，主链路、标识模型与拆分依据已稳定，本阶段不再有 `业务阻塞`。

剩余不确定性集中在外部接口：PGC 接口无公开文档、错误码全集未确认、合集失效成员与地区限制/DRM 表现未实测。这些按 `外部接口待补` 处理，用契约夹具与容错设计承接。

## 用户意图合同

- 字面请求：“「番剧/合集支持」做成一个正式 request”，并指出“这个地址明明是一个合集中的一个”“为什么不能获取 ep733316 这个地址的视频”。
- 实际目标：用户希望**粘一条合集内链接或一条番剧链接，就能看到该合集/该季的其它集并选择下载**，而不是自己一集一集去找 BV 号；并且不希望出现“看起来支持、实际下载失败”的假支持。
- 成功标准：
  1. 合集内任一 BV 链接解析后列出的可下载单元覆盖该合集的可见成员；
  2. 番剧 ep/ss 链接解析后列出该季的免费/限免集，其余集明确标注为不支持；
  3. 选中 N 个单元后生成 N 个互不串号的下载草稿；
  4. 无权限或不支持的集在解析结果中即被标记并解释，而不是下载阶段失败。
- 禁止解释（会满足字面但违背目标）：
  - 仅把 `ep733316` 映射成对应 `bvid` 后走普通视频链路——会丢掉整季列表，且清晰度被账号权限压缩（X6），用户仍然“拿不到其它集”；
  - 仅在文档/spec 中声明“支持合集”，但 UI 没有展开入口或集列表；
  - 把合集成员塞进现有 `parts`，却继续用顶层 `bvid` 生成任务（C15），导致逐集下载失败或下错内容；
  - 用“批量”作为默认行为，用户粘一条链接就被排队整季；
  - 用“只支持免费集”为由隐藏其余集，让用户以为整季都不可用。
- 可接受方案：扩展输入识别与解析契约，让“集”成为可展开的容器、“分 P”成为可选单元；选集与批量沿用现有多选/全选/反选交互。
- 下游检查：`spec` 必须给出单元标识与任务字段；`plan` 必须覆盖“同一稿件既在合集又有多 P”的组合；`verify` 必须用真实链接与契约夹具证明覆盖数、串号、权限提示；`review` 必须逐条核对本合同的禁止解释。

## confirmed scope

- 合集内链接可展开为该合集的成员列表，并展开到分 P 粒度后批量选择下载。
- 番剧 ep/ss 链接可展开为该季的免费/限免集列表，同样展开到分 P 粒度。
- 合集与番剧共用同一套选集列表与选择模型，用 P/EP 标签区分来源。
- 每个选中单元一个独立下载任务，任务可被现有队列、断点续传、通知链路消费。
- 不在支持范围内的集（登录专享/会员/付费/地区限制/禁止下载）在解析结果中即被标记并解释。
- 现有单视频、多分 P 的全部行为与契约保持不变。

## out-of-scope 与 non-goals

- 收藏夹、播放列表、稍后再看导入（S5 明确 V1.2 规划）。

- 登录专享、大会员、付费、DRM、地区限制内容的取流（H1 明确不做）。
- 直播流、课程（cheese）、付费课程。
- 弹幕、字幕下载，番剧评分/评论/追番状态。
- 自动把“整季下载”设为默认行为。
- 以本请求为借口重写 UGC 解析链路、替换 WBI 签名实现、更换下载器。
- 新增“合集管理”“批量重命名”“下载计划”等产品能力。

## confirmed decisions 与 invariants

1. 范围由 PRD 的“合集/番剧批量”与用户指令共同界定，两类都必须支持，不得只做其中一类。
2. **番剧支持集 = 内容本身免费或限免的集**；判据是内容属性，不看当前是否登录。登录专享、会员、付费、DRM、地区限制集一律不支持（H1）。
3. 登录态只影响支持集的清晰度上限（沿用 S6），不扩大支持集集合。
4. 合集与番剧共用统一选集列表；集是容器节点，分 P 是可选单元（H2、H4）。
5. 批量 = 多选手动勾选 + 全选/反选；不新增“整季一键加入”入口（H3）。
6. 现有 `E003`/`E004`/`E005`/`E006` 语义保持不变，新增场景复用而非改写。
7. 匿名能力边界不变：不因“支持番剧”把匿名上限提升到 1080P。
8. 单个下载任务始终对应一个可独立播放的媒体单元（一个分 P 或一集）。
9. 解析成功的判据是“有至少一个可下载单元”，而不是“接口返回 200”。

## 系统职责与边界

- 本仓库直接承接全部开发：Vue 3 前端、Tauri Rust 后端、任务与下载链路。本项目没有自建服务端。
- B 站公开接口是外部依赖：`/x/web-interface/view`、`/pgc/view/web/season`、`/pgc/player/web/playurl`、`/x/player/wbi/playurl`。
- 外部接口只提供数据与权限判定，不承担我们的产品语义；错误码到用户文案的映射由本仓库拥有。
- 复用的既有能力：输入归一化、WBI 签名与缓存、playurl 选择、音频/视频源选择、任务队列、断点续传、通知。不得为番剧另起一套。
- 合集与番剧的“统一选集列表”属于本仓库的前端模型，不是 B 站字段的直出。

## 面向开发者的行为细节

**标识模型**

- 一个“可下载单元”的完整标识是四段：来源类型（UGC 单稿 / 合集成员 / 番剧集）+ 稿件标识（`bvid`/`aid`）+ 流标识（`cid`）+ 剧集标识（`ep_id`，仅番剧）。
- 合集成员与番剧集都自带 `bvid` 与 `cid`（X1、X3），因此不能再用“顶层 bvid + 单元 cid”表达（C15 现状会串号）。
- 番剧必须携带 `ep_id`，因为 PGC 取流需要它（X5），而 `bvid` 不保证等价。
- 同一稿件可以既属于某个合集、自身又包含多个分 P。此时“集”是容器，“P”是单元；两者都要能表达，且容器本身不是下载单元。
- 分 P 的 `page` 会因删除重排，集号同样可能因下架变化；任务持久化不得以序号作为唯一标识。

**层级与选择**

- 统一列表的节点有两类：容器（集/稿件）与单元（分 P）。
- 只有单元可生成任务；容器只表达分组与批量选择意图。
- 一个番剧集通常只有 1 个分 P（X3），仍按同构处理：单 P 的集可直接呈现为可勾选单元，不需要用户多点一次。
- 容器与单元的勾选联动、部分选中态、全选/反选的作用粒度属于交互细节，来源未规定；记录为 Q9（非阻塞），spec 必须显式写死一种行为。

**时长**

- UGC `view.duration` 与 `pages[].duration` 为秒；PGC `episodes[].duration` 为毫秒（X3）。适配层必须归一，否则番剧时长会显示成 20 分钟×1000。

**可见性与权限**

- 支持判据：内容本身免费或限免，匿名状态即可取得非试看流；判定依据可以是接口的 `badge`/`need_login`/`need_vip`/`is_preview`/`rights.allow_download` 组合，具体在 spec 固定。
- 不支持集必须与“解析失败”区分：列表可见、置灰、附原因，不可勾选。
- 预告/花絮类条目（`section_type=1`）默认不进入可下载集，仅记录（Q6 非阻塞）。
- `rights.allow_download=0` 的内容必须拒绝，即使能播放。
- 地区限制（`area_limit`）与 DRM（`is_drm`）的表现未实测，一律按不支持处理并提示。

**合集成员有效性**

- 合集成员可能失效（下架/删除/私有），`ep_count` 与实际可枚举成员可能不一致。解析结果必须容忍缺员，不能因单集失效整单失败。
- 合集可能有多个 `sections`（正片/预告/花絮）；默认只展示可下载的正片 section（Q6）。

**任务与校验**

- 下载前必须用“该单元自己的标识”重新解析并校验，不能沿用顶层稿件的 `pages` 校验（C12）。
- 校验失败的语义应为“该单元已不可用”（`E004`），而不是“输入无效”。
- 任务持久化字段必须能区分 UGC 单元与番剧单元，并支持任务恢复后重新取流。

**错误与提示**

- 输入类：非法链接、无法识别的 ep/ss、不存在的稿件 → `E003`/`E004`。
- 权限类：登录专享 → `E005` 语义可复用但文案需指明“本版本不支持登录专享集”；大会员/付费/地区限制/禁止下载 → `E006` 语义复用并区分原因。
- 网络类：`E001`/`E002` 沿用。

## 工作流与依赖评估

1. 输入识别与单元标识是全部下游的前置；它决定解析端口签名与任务字段。
2. 元数据解析依赖外部接口事实（X1、X3），必须先落契约夹具，否则无法回归。
3. 选集 UI 依赖“单元列表 + 可见性标记 + 层级”契约；契约先行，UI 后行。
4. 下载链路改造依赖任务标识扩展；若任务字段不变，则必然串号，不能靠前端规避。
5. 权限提示依赖错误码语义，而错误码语义必须先在 spec 固定，否则文案会与后端不一致。
6. 与既有多 P 功能的耦合点在“选集模型”与“任务校验”两处，必须同批修改，不能只改一侧。

## 阻塞项分级与处理口径

- `业务阻塞`：无。H1–H4 已于 2026-11-14 由用户确认并记录。
- `外部接口待补`：PGC 字段与错误码全集、合集失效成员状态、地区限制与 DRM 表现。用契约夹具与容错设计承接，但不得写成“已确认”。
- `非阻塞`：Q5（序号定义）、Q6（预告/花絮）、Q8（`?p=`）、Q9（勾选联动）。给出默认值并在 spec 记录，评审可改。

## 减少二次确认的开发提示

- spec 不得重新讨论：范围仅合集+番剧、只支持免费/限免集、统一选集列表、展开到 P、多选批量、收藏夹/系列/直播/课程不做、现有 UGC 行为不回归。
- 已暴露、无需再问产品的隐藏问题：单元标识、PGC 毫秒、`allow_download`、登录态刷新、失效成员容错、树形联动默认。
- 可用适配边界先行的部分：PGC 字段以实测契约为准，缺失字段用 `Option` + 显式降级，不得静默填充。
- 必须停下的部分：外部接口待补项未实测时，不得写成“支持全部番剧”。
- 下游不得合并或互换的责任：Rust 拥有权限判定与标识归一，前端只消费；前端不得自行判定“可看/不可看”。
- 后续验收必须覆盖：两集合集的串号检查、免费/限免/登录专享三态提示、毫秒时长、既有分 P 回归、树形选择与草稿数量一致。

## 拆分策略

拆 4 个模块，按依赖顺序交付：

1. `episode-identity-and-contract`：输入识别、单元标识模型、解析结果与任务契约扩展（含 bvid/cid/ep_id、层级、可见性字段）。只做模型与契约，不做 UI。
2. `episode-metadata`：合集（`ugc_season`）与番剧（`pgc/view/web/season`）元数据端口与适配，含时长归一、集列表容错、section 过滤。
3. `episode-download`：PGC 取流、权限矩阵落地、任务侧归属校验、命名规则。
4. `episode-selection-ui`：统一选集列表（容器/单元、P/EP 标签、置灰与原因、勾选联动）、错误与提示。

应保持在一起：标识模型与契约扩展（1）不可拆，否则下游会出现两套标识。不得合并：UI 不得与契约同批“顺带改”，否则无法独立验证；元数据适配不得与取流混在一起，取流依赖权限矩阵。

## 下游阶段信号

- `page-design`：模块 4 必需。重点在容器/单元两级呈现、置灰原因、勾选联动、与现有分 P 区块的统一。
- `architecture-design`：模块 1、2、3 必需（跨端口、适配、任务模型的共享契约与重复语义风险）。
- `spec`：模块 1、3 最先需要；模块 2 依赖外部接口待补项；模块 4 依赖模块 1 契约。
- 特殊顺序约束：契约（1）必须先于 UI（4）；任务字段（3）必须先于取流改造落地，因为校验依赖它。
