# 澄清：取流与权限

## Q1：番剧解析的代表集怎么选？

- `ep` 输入用该集；`ss` 用第一个 `playable` 单元。
- 取流失败降级为空能力，不使解析失败。
- 锚定：source-derived（模块 2 能力为空状态的收口）。

## Q2：权限错误码怎么分？

- 会员/付费/禁止下载/地区 → `E006`（有权限语义但不允许）。
- 需要登录（badge 或接口 -101）→ `E005`。
- 集不存在/cid 不匹配 → `E004`。
- `epId` 缺失（任务数据非法）→ `E003`。
- 锚定：confirmed-decision（复用既有错误码语义）。

## Q3：`containerKind` 为什么要进任务？

- 命名规则按“合集/季 vs 单视频”分流，任务在重启后仍要能算出同样的文件名。
- 决定：草稿与任务都携带，默认 `video`，旧任务兼容。
- 锚定：source-backed（S7）+ code-fact-backed（持久化）。

## Q4：合集成员走哪条取流？

- 成员是普通稿件，`source=ugc`，走既有 UGC 取流；不因属于合集而走 PGC。
- 锚定：source-derived。

## Q5：登录态变化后怎么办？

- 重新按当前登录态取流；若该集已不可下载，任务失败并给出权限错误；不自动换集、不静默降级清晰度到其它单元。
- 锚定：source-backed（S6）+ 不变量 8。

## Q6：PGC 取流失败一律 E004 吗？

- 已确认 `-403`/`-10403` 映射 `E006`；其余非 0 保持既有 `map_api_error` 默认 `E004`，不臆造错误码。
- 锚定：external-interface-pending。
