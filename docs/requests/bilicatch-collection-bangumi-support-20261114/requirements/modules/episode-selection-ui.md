## 业务意图

让用户在同一个列表里看清“这是合集第几集/这一集的第几个 P”，并能在不清楚技术细节的前提下完成批量选择；避免为了番剧再造一个平行列表，造成两套选择状态。

## 用户可见范围

- 一个选集区，节点为容器（集）与单元（分 P）。
- 单 P 集直接呈现为可勾选单元，不强制用户展开。
- 多 P 集显示为可展开容器，展开后出现 P1…Pn。
- 不可下载集：可见、置灰、附原因，不可勾选；不计入“已选 n/m”的 n。
- 全选/反选作用于全部可勾选单元。

## 表单、表格、展示与交互

- 每个单元行：复选框、`P{n}` 或 `EP{n}` 标签、标题、时长。
- 容器行：展开/收起控件、`EP{n}` 标签、集标题、可选时显示复选框。
- 计数：“已选 n/m”，m 为可勾选单元总数。
- 批量工具：全选、反选，与既有行为一致。
- 不可选态：无复选框或禁用复选框 + 原因文案。
- 空态：无可用单元时说明原因（解析失败归错误区，不可下载归空态说明）。

## 流程与状态规则

1. 解析成功后生成列表；默认选中第一个可勾选单元（Q8：忽略 `?p=`）。
2. 勾选/取消更新选中集合；容器勾选默认联动其全部子单元（Q9 默认）。
3. 入队按钮的可用性与既有规则一致：至少一个单元 + 参数有效。
4. 登录态变化导致可用性变化时，刷新列表与选中集合，已失效单元移出选择并提示。
5. 解析请求竞态保护沿用现有 token 机制。

## 依赖与影响面

- 前置：模块 1 契约、模块 2 数据。
- 影响：`PartSelector.vue`、`store.ts`（选中集合与草稿）、`DownloadPage.vue`、locale、样式。
- 相邻回归：单视频与多分 P 的选集体验、入队数量、任务草稿字段。

## 前端 / 后端责任边界

- 前端：列表结构、展开/收起、选中状态、计数、禁用与原因展示、文案。
- 后端：提供单元层级与可用性数据，不提供展示决策。
- 共享契约：单元层级字段与可用性枚举。
- 前端不得自行判断“能不能下载”，只消费后端给出的可用性。

## page-design 路由

需要：本模块改变解析页的选集信息架构与交互结构，必须先做 `page-design`，重点覆盖两级列表、置灰原因、与既有分 P 区块的合并、窄宽度下的可读性。

## 下游 spec 义务

- 明确列表数据结构与渲染规则（单 P 集、多 P 集、混合合集）。
- 明确 P/EP 标签、计数口径、全选/反选粒度。
- 明确置灰与原因文案的触发条件与文案键。
- 明确空/加载/失败态。
- 明确勾选联动（Q9）与默认选中（Q8）。
- 明确登录态变化后的刷新与已选清理。

## 开放问题

- Q9：容器勾选是否联动全部子单元（默认联动），需在 page-design 与 spec 同步固定。
- 单 P 集是否显示容器层（默认：不显示容器层，直接作为单元），需在 page-design 定稿。
