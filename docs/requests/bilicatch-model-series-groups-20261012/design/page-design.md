# 页面设计：模型系列分组

## Delivery Unit

`bilicatch-model-series-groups-20261012`

## 页面目标与场景

用户在模型管理弹窗中先按系列定位模型，再在同系列内比较大小、用途和安装状态。成功标志是两个系列边界清晰，原操作路径不变。

## Source And Allowlist Mapping

- 系列容器与标题：`SRC-01`。
- Whisper 和 FireRedASR2 的归属：现有模型 ID 合同。
- 下载、取消、删除、默认标记和进度：保留现有行为，不新增产品语义。

## 信息架构与布局

- 保留弹窗标题与按需下载提示为最高层级。
- 模型区域改为垂直系列列表；每个系列由紧凑标题和现有模型行组成。
- 系列标题使用小型、中等强调文本，不使用嵌套卡片；系列之间用间距区分。
- 模型行内部网格、进度条和操作区保持不变。

## 交互与状态

- 系列不折叠，不增加新的点击或键盘操作。
- 空系列不渲染；整体模型为空时沿用现有空白表现，不新增未授权文案。
- 加载、失败、下载、校验、已安装和使用中状态沿用模型行现有反馈。

## 响应式与可访问性

- 弹窗宽度和现有响应式行为不变；分组只增加垂直结构，不引入横向溢出。
- 每个系列使用带 `aria-labelledby` 的语义分区，标题使用稳定 ID。
- 分组不依赖颜色传达归属；用文本标题明确标识系列。

## 样式和组件边界

- 沿用项目现有 `transcription.css` 和语义 class 约定，不引入新样式框架或内联样式对象。
- 仅新增分组容器、标题和组内列表样式，使用现有颜色令牌。
- 不拆出新 Vue 组件：分组仅在 `ModelManager` 中使用，无独立交互生命周期，拆分会形成单调用者透传层。

## 风险与缓解

- 风险：未来新模型 ID 漏配分组。缓解：分组映射使用 `Record<AsrModelId, ModelSeries>` 的穷尽类型检查。
- 风险：分组后事件参数变化。缓解：模型行不拆分，现有 emit 断言继续覆盖。
- 未决 UI 问题：无。
