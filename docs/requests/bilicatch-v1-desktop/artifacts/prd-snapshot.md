# PRD 结构化快照

## 来源摘要

- 产品：BiliCatch
- 定位：基于 Tauri 的跨平台 B 站音视频下载桌面工具
- 平台：Windows、macOS、Linux
- 用户：需要离线保存内容的学习者、创作者和媒体归档用户
- V1.0 范围：单视频/音频、合集/番剧批量、独立音频、扫码登录、队列与断点续传、系统集成、自动更新
- 明确非目标：直播录制、弹幕、视频编辑/转码、字幕、播放列表/收藏夹导入

## 关键业务目标

- 提供稳定、高效的视频和音频下载能力，并支持独立音频输出。
- 使用原生桌面托盘、通知、文件对话框和窗口管理形成完整桌面体验。
- 匿名可用；登录后解锁更高清晰度、HiRes/无损与账号有权访问的受限内容。
- 主程序小于 15MB（不含 FFmpeg）、冷启动小于 1.5 秒、空闲内存小于 80MB。

## 明确行为约束

### 全局结构

- 单窗口、侧边导航、Hash 路由。
- 路由：`/download`、`/tasks`、`/login`、`/settings`。
- 顶部栏：返回、应用名、登录状态入口、设置入口。
- 侧栏：下载中心、任务列表、设置。
- 前端使用 Pinia 管理全局状态，`vue-i18n` 提供简体中文与英文结构。
- Rust 后端按 Command / Service / Infrastructure 分层，IPC 均返回 `Result<T, AppError>`。

### 解析输入与状态

- 支持标准视频 URL、移动端 URL、`b23.tv` 短链、BV/AV 纯 ID、带 `p` 参数的多 P 链接。
- 输入为空时解析按钮禁用；有效剪贴板或拖拽链接可自动填充并触发解析。
- 解析时展示加载态；成功展示封面、标题、UP 主、时长、分 P 和媒体选项。
- 多 P 默认选中第一集，支持全选/反选。
- 清空操作同时清空输入、结果和已选参数并恢复初始态。
- 解析结果缓存到 Pinia，避免同一输入的重复请求。
- WBI 密钥约缓存 12 小时；签名失败自动刷新密钥并重试一次。
- 异常覆盖无效链接、不存在/删除、地区限制、需要登录、WBI 签名失败和网络超时。

### 下载参数与队列

- 下载类型为“视频+音频”“仅视频”“仅音频”的单选模式。
- 仅音频模式隐藏清晰度/编码，展示格式/码率；视频相关模式执行相反显示规则。
- 已解析且选择分 P 后允许加入队列；成功提示并跳转 `/tasks`。
- 任务队列上限 100；超过上限禁止添加并提示。
- 文件名移除 `\\ / : * ? \" < > |`，最长 200 字符。
- 临时文件在完成后删除；取消任务时立即删除。

### 权限约束

- 匿名视频最高 480P；登录后根据账号与视频源最高 8K/HDR。
- 匿名音频最高 64K；登录后最高 192K + HiRes 无损。
- FLAC 要求登录且视频源支持。
- 不绕过付费内容保护，只下载用户有权访问的内容。

### 音频下载

- 输出 MP3（128K/192K/320K）、M4A 原始码率、FLAC 无损。
- MP3/FLAC 通过内置 FFmpeg 转换；M4A 可直接封装/保存。
- 任务阶段包括获取音频流、下载、格式转换、写入元数据、完成/失败。
- 元数据至少包括标题、UP 主、封面；失败保留可重试的错误原因。

### 视频下载与合并

- 支持 AVC、HEVC、AV1（按源可用流）；清晰度按账号能力和源展示。
- “视频+音频”并行下载 DASH 视频/音频流，再调用内置 FFmpeg 无损封装。
- “仅视频”只下载视频流，不调用合并。
- 合并失败以 `E008` 暴露；中断按规则自动重试。

### 任务表格与操作

- `/tasks` 展示筛选标签：全部、下载中、已完成、失败。
- 表格/列表至少展示文件名、状态、进度、速度、剩余时间、大小和操作。
- 下载中任务可暂停/取消；暂停任务可恢复/取消；失败任务可重试/删除；完成任务可打开文件或所在目录/删除记录。
- 顶部支持“暂停全部”“清除已完成”；取消或退出时对正在下载任务进行确认。
- 进度由 Rust 事件推送，前端实时更新；应用重启后恢复未完成任务。
- 最大并发任务数默认 3、范围 1-10；单任务连接数默认 8、范围 1-32。

### 登录与认证

- `/login` 通过 B 站二维码登录；生成二维码后轮询状态。
- 状态分支：未扫码、已扫码待确认、已确认、已过期、已取消。
- 已扫码时提示在手机确认；成功后获取 Cookie、加密保存并刷新状态。
- 二维码约 180 秒过期，过期停止轮询并提供刷新。
- 应用重启恢复登录；手动退出清理 Cookie；每次解析前检测有效性。
- 登录非强制，匿名状态保留基础下载。

### 设置表单

- 下载设置：下载目录、临时目录、最大并发任务数、单任务连接数、默认视频清晰度、默认音频格式。
- 外观设置：亮色/暗色/跟随系统主题，简体中文/English 语言。
- 系统设置：下载完成通知、关闭窗口行为、自动检查更新。
- 关于：版本号、检查更新、开源许可。
- 所有设置即时保存，无手动保存按钮；主题和语言即时生效。
- 目录按钮调用系统目录选择器；滑块实时显示数值并在释放后保存。
- 默认下载目录 `~/Downloads/BiliCatch`，临时目录为系统临时目录；默认 3 个并发任务、8 个连接、1080P、MP3、跟随系统、通知开启、最小化到托盘、自动更新开启。

### 系统集成

- 托盘菜单：显示主窗口、暂停所有、退出；有下载中任务时退出需确认。
- 通知：下载完成、下载失败、发现更新。
- 文件对话框：选择目录、打开文件位置。
- 记忆窗口位置/大小；关闭行为可配置。
- 启动时自动检查更新，签名验证后静默下载并提示安装。
- 支持拖拽链接到窗口后自动解析。

### 错误码

| 代码 | 场景 | 用户提示 |
| --- | --- | --- |
| E001 | URL 格式无效 | 请输入有效的B站链接 |
| E002 | 视频不存在 | 视频不存在或已被删除 |
| E003 | 需要登录 | 请先登录以获取该清晰度 |
| E004 | 地区限制 | 该视频在当前地区不可用 |
| E005 | WBI 签名失败 | 请求签名失败，请稍后重试 |
| E006 | 网络超时 | 网络连接超时，请检查网络 |
| E007 | 磁盘空间不足 | 磁盘空间不足，请清理后重试 |
| E008 | FFmpeg 执行失败 | 媒体处理失败，请检查 FFmpeg |
| E009 | 下载中断 | 下载中断，已自动重试 |
| E010 | 二维码过期 | 二维码已过期，请刷新 |

| 页面/容器 | 输入或展示 | 核心交互 |
| --- | --- | --- |
| 下载中心 | URL、封面、标题、UP 主、时长、分 P、类型、清晰度、编码、音频格式、码率、保存目录 | 解析、剪贴板自动解析、拖拽解析、选择分 P、切换下载类型、加入队列、清空 |
| 任务列表 | 筛选、文件名、状态、进度、速度、剩余时间、大小、上下文操作 | 暂停、恢复、取消、重试、打开、删除、暂停全部、清除完成 |
| 登录页 | 二维码、扫码状态、用户状态 | 刷新二维码、轮询、确认提示、退出登录 |

| 托盘/系统 | 主窗口状态、任务状态、系统通知 | 唤起、暂停全部、确认退出、文件定位、更新安装 |

## 工作流与状态规则

1. 解析：输入 -> 前端校验 -> `parse_video` -> ID 规范化 -> 登录检查 -> WBI 请求 -> 响应适配 -> 展示或错误提示。
2. 下载：确认参数 -> `create_download_task` -> 排队 -> 下载/处理 -> 事件推送 -> 完成、暂停、取消或失败。
3. 登录：请求二维码 -> 展示 -> 轮询 -> 扫码/确认/过期/取消分支 -> Cookie 加密持久化 -> 状态刷新。
4. 设置：用户更改 -> UI 即时生效（适用时）-> store 持久化 -> 后续任务读取新配置。
5. 发布：版本号一致 -> FFmpeg 与图标齐备 -> 各平台构建 -> 签名/公证 -> 生成 `latest.json` 和 `.sig` -> GitHub Releases。

## 技术与交付约束

- Tauri v2，Vue 3.5+，TypeScript 5.x，Vite 6.x，Naive UI 2.x，Pinia 2.x。
- Rust 使用 Tokio、reqwest、serde、thiserror、哈希/签名、URL/regex 等。
- FFmpeg 7.x 作为 `externalBin` sidecar 随安装包分发。
- 自动更新使用 Ed25519 签名；Cookie 仅在本地加密存储。
- Windows 10 1809+ x64；macOS 10.15+ x64/ARM64；Ubuntu 20.04+/Fedora 36+ x64。
- 安装包目标含 NSIS/MSI、DMG/App、deb/rpm/AppImage；发布产物命名遵循 PRD。

## 相关模块与页面

1. 共享应用壳与契约，无独立业务页。
2. 解析、音频下载、视频下载共用 `/download`。
3. 任务管理位于 `/tasks`。
4. 登录位于 `/login`。
5. 设置位于 `/settings`。
6. 系统集成无独立路由。

## 上游开放问题

- PRD 未提供真实 GitHub Releases 仓库、更新端点、公钥与签名材料。
- PRD 未提供各平台 FFmpeg 可执行文件、应用图标、Windows 签名证书和 Apple 公证凭据。
- PRD 未固定 B 站 API 端点与响应契约版本；该外部接口存在持续变化风险。
- “下载速度提升 30%”与“多线程至少为单线程 3 倍”基准口径不一致，需在验证阶段分别记录为目标而非保证。
- 合集/番剧的受限内容与账号权限依赖真实账号和线上环境，自动化测试需要契约夹具或授权测试账号。
