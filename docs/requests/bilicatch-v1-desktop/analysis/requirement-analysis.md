# BiliCatch V1.0 需求分析

## 分析结论

该请求是一个从零交付的跨平台桌面应用，不是单页原型。需求主链路完整，产品范围、页面入口、主要状态、权限边界、错误码和技术栈均已明确，可以进入模块拆分。真实 B 站接口细节、发布凭据和跨平台 FFmpeg 二进制尚未提供，但不改变产品语义；下游必须通过稳定领域契约、可替换适配器、模拟夹具和显式配置承接，不能把外部不确定性扩散进页面与状态模型。

## 已确认范围

- 新建 Tauri v2 + Vue 3 + TypeScript + Vite 桌面应用及 Rust 后端。
- 实现应用壳、Hash 路由、全局状态、主题和国际化基础。
- 实现 `/download` 的解析、分 P、媒体选项和入队流程。
- 实现音频的 M4A 保存及 MP3/FLAC 转换流程。
- 实现 DASH 视频/音频下载、仅视频模式和 FFmpeg 合并流程。
- 实现 `/tasks` 的筛选、实时进度、暂停、恢复、取消、重试、打开和清理。
- 实现 `/login` 二维码登录状态机、Cookie 本地加密存储、恢复和退出。
- 实现 `/settings` 全部设置项、默认值、即时持久化与即时换肤/切语言。
- 实现托盘、通知、文件对话框、窗口行为、拖拽和自动更新的系统边界。
- 提供测试、开发启动、生产构建和 Tauri 打包配置。

必须贯穿所有下游阶段的约束包括匿名/登录能力差异、100 项队列上限、文件名规则、临时文件清理、统一错误码、Cookie 本地加密、FFmpeg sidecar、版本一致性和平台兼容性。

## 范围外与非目标

- 不实现直播流录制、弹幕、字幕、视频编辑或通用视频转码器。
- 不实现播放列表或收藏夹导入。
- 不绕过付费、地区、账号权限或平台内容保护。
- 不自建云端用户系统、代理下载服务或 Cookie 上传服务。
- 不承诺在缺少签名证书、公证凭据和各平台运行环境时完成真实商店/Release 发布。
- 不把“未来多平台解析”扩展为本期 YouTube/Twitter 实现；仅保留合理的解析服务边界。
- 不为追求架构形式而引入没有真实变化点的工厂、管理器或多层包装。

| 主题 | 决策/不变量 |
| --- | --- |
| 技术栈 | Tauri v2、Vue 3.5+、TypeScript 5.x、Vite 6.x、Naive UI 2.x、Pinia 2.x |
| 路由 | Hash 模式，`/download` 为默认业务页，另含 `/tasks`、`/login`、`/settings` |
| 登录策略 | 匿名可用，登录只提升能力；每次解析前验证 Cookie |

| 质量 | 测试覆盖可测试行为；静态检查和生产构建作为交付门禁 |

## 有来源依据的行为清单

### 下载中心

- URL 输入为空时解析禁用；支持粘贴、剪贴板识别和拖拽自动解析。
- 成功结果显示封面、标题、UP 主、时长；多 P 显示选择列表并默认第一项。
- 类型切换控制视频参数与音频参数的条件显示。
- 加入队列需要已解析和至少一个分 P；完成后提示并跳到任务页。
- 清空必须同时复位输入、解析结果和选择状态。

### 任务管理

- 筛选维度为全部、下载中、已完成、失败。
- 每项显示文件名、状态、进度、速度、剩余时间、大小以及状态相关操作。
- 状态操作集严格随下载中、暂停、失败、完成而变化。
- 进度来自 Rust 事件；重启要恢复未完成任务。

### 登录

- 二维码生成、显示、轮询、扫码待确认、确认成功、过期和取消构成完整状态机。
- 二维码约 180 秒后过期并停止轮询，允许刷新。
- 成功后加密存储 Cookie；退出删除；启动恢复。

### 设置

- 路径、并发、连接数、默认清晰度、默认音频格式、主题、语言、通知、关闭行为、自动更新均即时保存。
- 范围控件、默认值和枚举项均由 PRD 固定。
- 关于区显示版本、检查更新并打开许可页面。

### 系统集成

- 托盘具有显示、暂停所有、退出；存在活动任务时退出确认。
- 下载完成、失败和更新可用触发系统通知。
- 选择目录、打开位置、窗口几何记忆、关闭行为和链接拖拽由 Tauri 系统边界实现。

## 面向开发的行为细化

### 角色、权限与可编辑边界

产品只有本机用户角色，权限差异来自匿名/已登录状态和 B 站账号内容权限。匿名用户仍能编辑所有本地设置和管理本地任务；登录只改变解析得到的媒体能力。前端不得仅靠隐藏选项执行授权，创建任务前 Rust 必须再次校验能力。

### 表单与验证

- URL 字段允许五类来源格式，空值禁用，格式失败映射 E001。
- 解析结果出现前不能编辑媒体选择；加载期间应防止重复提交。
- 多 P 选择至少保留一个项目，否则入队不可用。
- 音频格式决定码率选项：M4A 使用原始码率，MP3 使用枚举码率，FLAC 无损且受登录/源能力约束。
- 下载与临时目录由目录对话框选择；设置页路径展示应可读，保存失败必须反馈而非静默丢失。
- 两个数值设置强制范围校验，不能仅依赖滑块 UI。

### 列表、状态与操作

- 任务至少需要 queued/downloading/paused/processing/completed/failed/cancelled 内部状态，UI 可将 queued/processing 归并到 PRD 可见筛选。
- 取消是终止性操作并清理临时文件；删除完成/失败记录不应误删输出文件，除非界面明确提供此语义，而 PRD 当前没有。
- “清除已完成”只清记录；“暂停全部”只影响可暂停的活动任务。
- 未完成任务持久化必须包含恢复所需参数，而不是只保存进度展示字段。

### 异步、失败与重试

- 解析请求、二维码轮询、下载事件与更新检查都需要可取消或可停止的异步生命周期，避免页面卸载后继续写入失效状态。
- WBI 失败只自动刷新并重试一次；仍失败返回 E005。
- 网络超时返回 E006；下载中断以 E009 表示并保留自动重试事实。
- FFmpeg 非零退出、找不到 sidecar 或输出缺失统一归入 E008，但日志需保留技术原因。
- 任务失败必须保留原参数，使重试不要求用户重新解析。

### 数据来源与适配边界

- B 站响应不是前端契约。Infrastructure 将外部响应映射为稳定领域对象，再由 Command 序列化为前端 DTO。
- 任务事件携带稳定 task id、状态、已完成字节、总字节、速度和可选剩余秒数；前端按 task id 合并更新。
- 设置值在前后端共享契约中具有同一枚举与范围定义；持久化数据需要版本/默认值回退。
- 外部更新 JSON 与内部更新视图模型之间保留适配层。

## 隐含需求与隐藏假设

| 来源线索 | 隐藏问题 | 当前立场 | 影响与承接 |
| --- | --- | --- | --- |
| 重启恢复未完成任务 | 哪些中间状态可以安全恢复 | 推导，需在规格固定 | 任务状态机；持久化原参数并将下载中/处理中恢复为可继续或排队 |
| Cookie 加密保存 | 密钥从哪里来 | 外部实现决策待架构确认 | 安全边界；使用 OS 可用安全能力或应用本地密钥方案，禁止硬编码固定明文密钥 |
| 删除任务操作 | 是否同时删除输出文件 | 非阻塞歧义 | 默认仅删记录，规格必须显式记录，不能扩大为删除用户文件 |
| “静默下载 + 提示安装” | 是否允许后台自动安装 | 非阻塞歧义 | 更新状态机；默认只在用户确认后安装 |
| 合集/番剧 | 是否与普通多 P 共享模型 | 外部接口待补 | 解析适配器规范化为统一 part 列表 |
| 打开文件所在位置 | 三平台命令差异 | 已确认需求，技术待设计 | 系统适配器隐藏平台差异 |
| 速度目标 | 测量样本、网络和基线未定义 | 非阻塞 | 作为基准测试目标记录，不能声称绝对保证 |
| 英文语言包“预留”与语言可选 English | 英文是否必须完整 | 业务语义存在轻微冲突 | 用户可切换 English 意味着 V1 应提供核心 UI 英文文案，否则设置无效 |

## 工作流与依赖判断

1. 共享契约和应用壳是所有页面与后端模块的基础，应最先交付。
2. 解析结果模型是音频、视频和批量任务创建的上游，必须先于下载实现。
3. 任务领域模型和事件协议同时被音频、视频、任务页、托盘和通知消费，应在下载执行前稳定。
4. 登录改变解析能力，但匿名解析必须可独立工作；先定义认证状态契约，再接真实二维码 API。
5. 设置影响队列并发、连接数、默认媒体选项、主题、语言、通知和窗口行为，应有集中且版本化的配置模型。
6. 系统集成依赖前述任务、设置和认证状态，适合最后接入。

## 歧义与澄清登记

| 问题 | 分类 | 为什么重要 | 下游处理 |
| --- | --- | --- | --- |
| 删除任务是否删除输出文件 | 非阻塞 | 误删用户文件风险高 | 规格固定为仅删记录，除非用户另行要求 |
| Cookie 加密密钥策略 | 外部/平台实现待补 | 决定安全强度和跨平台行为 | 架构阶段选择可测试的凭据存储端口，记录平台降级 |
| B 站 API 与 WBI 的精确端点/字段 | 外部接口待补 | 接口会变化且 PRD 未定义 | 建立 adapter + fixture，真实接口集中配置 |
| 自动更新安装是否自动执行 | 非阻塞 | 影响重启和用户控制 | 采用发现/下载提示，安装需用户确认 |
| 速度指标的可重复基准 | 非阻塞 | 受网络/CDN 影响 | 验证报告说明环境并区分功能门禁与性能观察值 |
| 完整英文覆盖范围 | 非阻塞 | 设置中已有 English 选项 | 核心 UI、状态和错误文案提供中英文；第三方/系统文本不保证 |

不存在阻止 requirement-splitting 的业务歧义。

## 风险与约束评估

| 风险 | 来源/触发 | 影响面 | 失败模式 | 下游保护 |
| --- | --- | --- | --- | --- |
| B 站 API/WBI 变化 | 外部响应或签名算法改变 | 解析、登录 | 全部请求失败、字段缺失 | 稳定领域端口、响应夹具、单点适配、错误映射测试 |
| HTTP 412/限流 | 请求过密或请求头异常 | 解析、下载 | 拒绝访问 | 真实 UA/Referer、节流、有限重试、可诊断日志 |
| 任务恢复损坏 | 应用在下载/合并时退出 | 队列、文件 | 幽灵状态、坏文件 | 原子持久化、临时后缀、恢复规则测试 |
| Cookie 泄露 | 明文日志或固定密钥 | 登录、安全 | 账号凭据暴露 | 脱敏日志、凭据端口、禁止前端持久化明文 |
| FFmpeg 缺失/不兼容 | sidecar 未打包或架构错误 | 音频/视频 | E008、无法交付 | 启动能力检测、命令参数测试、打包检查 |
| 平台系统 API 差异 | Windows/macOS/Linux 行为不同 | 托盘、窗口、打开文件 | 单平台可用 | 系统端口、平台条件编译、跨平台手测清单 |
| 队列并发竞态 | 暂停/取消/事件同时发生 | 任务 | 状态倒退、重复写入 | 单一状态所有者、显式转移、并发测试 |
| 外部发布材料缺失 | 无证书、公钥、二进制 | 打包发布 | 无法签名/公证 | 区分代码完成与外部发布门禁，提供占位校验失败而非伪造材料 |

## 阻塞项分类与处理口径

### 业务阻塞

无。现有 PRD 足以确定主链路、页面、权限与状态语义。

### 外部接口待补

- B 站 API/WBI/二维码响应的实时契约：通过 Rust adapter、DTO 映射和测试夹具承接。
- GitHub Releases 更新端点与 Ed25519 公钥：通过构建配置/环境注入，未配置时返回可识别的不可用状态。
- FFmpeg 各平台二进制及发布签名材料：实现与验证可先使用本机可用 sidecar 或 mock，真实发布前必须补齐。

### 非阻塞

- 删除任务默认只删除记录。
- 自动更新安装由用户确认。
- 核心界面提供中英文。
- 性能指标在可控环境记录观察值，网络型指标不作无条件保证。

## 减少二次确认的开发提示

- 下游不得重新讨论技术栈、路由、登录策略、错误码、队列上限和设置默认值。
- 外部响应字段不完整时停留在 adapter 层处理，不得让页面直接依赖原始 JSON。
- 删除、退出、取消等高风险动作采用保守语义并保留确认。
- 任务状态转移、登录轮询和设置默认值必须写入可执行规格与测试。
- 发布材料缺失不阻塞核心工程开发，但禁止声称已完成真实签名、公证或多平台安装验证。

## 拆分策略

需要模块化且顺序交付。拆分依据是稳定的业务/平台边界与依赖顺序，而不是简单按 PRD 章节机械拆分。

- 应用基础与共享契约保持在一个模块，提供应用壳、路由、类型、错误和 mock/IPC 边界。
- 解析与下载中心保持在一个模块，因为输入、结果、分 P 与下载参数共享同一页面状态。
- 音频执行和视频执行分别拆开，因为 FFmpeg 行为、参数与失败模式不同。
- 任务管理独立，因为其状态机和恢复机制被多个下载类型共用。
- 登录、设置分别独立，避免权限与配置状态混入下载页面。
- 系统集成与发布保持一个末尾模块，消费前面模块的稳定接口。

解析页面、音频参数、视频参数不能合并为一个模糊“大下载功能”；任务核心也不能只作为任务页面的局部实现。

## 下游阶段信号

- 页面设计：应用基础、下载中心、任务管理、登录、设置均需要；纯后端音频/视频执行与系统发布不需要独立页面设计。
- 架构设计：全部模块均涉及代码/类型/边界；系统集成尤其需要平台适配边界。
- 顺序：基础 -> 解析/下载中心 -> 任务核心与页面 -> 登录 -> 设置 -> 音频 -> 视频 -> 系统集成与发布。音视频执行可在任务模型稳定后实现。
- requirement-splitting 必须明确共享 `/download` 页的模块归属，避免后续模块互相改写已批准规格。
