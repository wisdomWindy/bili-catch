# 页面设计：登录与认证

## 交付单元标识

`authentication`

## 页面目标

在现有 BiliCatch 工作台内提供可信、低干扰的 B 站扫码登录流程，让匿名用户清楚看到二维码当前状态、剩余有效时间和唯一下一步；已登录用户可核对本机账户并退出。登录不是下载中心的前置门槛，页面不得暗示匿名功能不可用。

## 目标用户或场景

- 匿名用户从顶栏或受限清晰度提示进入 `/login`，扫码解锁其账号有权访问的高清/无损能力。
- 用户扫码后需要在手机确认，并在桌面端得到明确、不过度刷新的状态反馈。
- 二维码过期、取消或请求失败后，用户可原位刷新/重试，不丢失进入前的返回路径。
- 已登录用户从顶栏进入，查看简要账户信息并主动退出。

## 布局结构

页面沿用 `AppShell` 的侧栏、56px 顶栏和内容滚动区。业务内容使用现有最大宽度与 24/16px 页面内边距，不创建独立全屏登录落地页。

```text
页面标题 / 简短状态说明
认证工具区（桌面双列，窄屏单列）
  左：固定二维码舞台 224x224
  右：状态标题、状态说明、剩余时间、当前主操作
底部：匿名仍可用的能力边界提示
```

已登录时，同一认证工具区替换为账户摘要：头像占位、昵称、账号标识、已登录状态与“退出登录”操作；不同时保留二维码，避免两个主流程竞争。

## 视觉层级

1. 页面 H1“账号登录”与一句当前模式说明。
2. 二维码或账户摘要是第一视觉焦点；二维码保持高对比白底和稳定 224px 方形，不用装饰渐变。
3. 状态标题为紧凑 18px，等待扫码使用中性色，待确认使用信息色，成功使用成功色，过期/取消/错误使用警告或危险色。
4. 倒计时是次级等宽数字，不以大字号制造紧迫感。
5. 主操作仅在过期/取消/错误时出现“刷新二维码/重试”；等待态不显示无效按钮。退出登录使用危险语义但不是页面首要视觉。

## 区块拆分

### 页面标题

- H1 与现有 Tasks/Download 页面同级，不重复顶栏标题的超大字号。
- 副文案随 auth snapshot：匿名时说明扫码用途，已登录时说明本机账号状态。

### 二维码舞台

- `requesting` 显示固定尺寸 skeleton，避免加载完成后布局跳动。
- `waiting_scan` 显示可扫描二维码；下方显示 `03:00` 至 `00:00` 倒计时。
- `waiting_confirm` 保留二维码但降低非必要强调，在状态区突出“已扫码，请在手机上确认”。
- `expired` / `cancelled` 在同尺寸舞台覆盖不可用状态图标和短文案，二维码不再可误扫。
- `error` 保留稳定占位，不显示损坏图片。
- 二维码容器是功能性 framed tool，圆角不超过 8px；页面其他 section 不包装为浮动卡片。

### 状态与操作

- 状态图标使用 Lucide，和文本共同表达，不只靠颜色。
- `aria-live=polite` 只朗读状态分支变化，不每秒朗读倒计时。
- 刷新/重试是图标加文本按钮，pending 时禁用并显示同尺寸 spinner；连续点击不得并发生成多个二维码。
- 页面卸载、二维码过期和登录成功均停止轮询，UI 不保留“仍在连接”的假状态。

### 已登录账户摘要

- 昵称为主文本；可用时显示头像与 B 站 UID，远程头像失败时使用 `UserRound` 占位。
- 顶栏认证入口同步显示昵称或截断后的账号名；窄窗口只保留头像图标和可访问名称。
- “退出登录”需要确认对话框，初始焦点放“保留登录”，关闭后归还触发按钮。

### 能力提示

- 匿名说明保持一行或两行：匿名仍可解析和使用基础下载；登录仅解锁账号允许的更高清晰度/音频能力。
- 不承诺固定 8K/HiRes，一切以解析结果和账号权限为准。

## 样式方向

- 复用现有灰白工作台、品牌粉、信息蓝、成功绿、警告橙和危险红，不引入单一色大面积背景。
- 使用分隔线与留白组织，不嵌套卡片，不添加装饰插画、渐变或氛围背景。
- QR 白色安全边界不随暗色主题反转；其外部工具区按现有 surface/border token 适配明暗主题。
- 所有文字 letter-spacing 为 0；按钮至少 36px，高频主操作建议 40px。

## 交互骨架

1. 进入 `/login` -> 读取认证快照。
2. 已认证 -> 展示账户摘要，不请求二维码。
3. 匿名 -> 请求二维码 -> skeleton -> 显示二维码并开始 2 秒轮询。
4. 未扫码 -> 保持二维码与倒计时；已扫码 -> 更新 live 状态，等待手机确认。
5. 已确认 -> 显示短暂成功状态 -> 顶栏立即更新 -> 返回来源页；无有效来源时到 `/download`。
6. 过期/取消 -> 停止轮询 -> 原位显示刷新按钮；刷新后替换 key/url 并重启 180 秒周期。
7. 请求/轮询错误 -> 停止当前周期 -> 显示可重试 inline error；不得泄露 Cookie、URL query 或响应原文。
8. 已登录点击退出 -> 确认 -> 清除成功后切回匿名二维码流程；失败保留账户摘要并显示错误。

## 响应式行为

- `>= 760px`：认证工具区为 `224px minmax(280px, 1fr)` 两列，整体宽度约 720-820px，左对齐内容区而非悬浮居中大卡。
- `< 760px`：改为单列，二维码舞台居中，状态/操作左对齐；页面允许纵向滚动。
- `< 520px`：页面沿用 60px 侧栏；二维码保持 224px，在剩余内容宽度不足时降至 `min(224px, 100%)`，始终保持 1:1；顶栏昵称视觉隐藏但 aria-label 保留。
- 中英文最长状态与按钮允许换行；不缩放字体，不让错误文本覆盖二维码或操作。

## 设计风险

- 每秒倒计时与 2 秒轮询可能造成辅助技术噪声；倒计时不放入 live region，只有状态枚举变化触发 polite 通知。
- 二维码若用 canvas，必须提供状态文本与可访问名称；不得把登录 URL 暴露为可复制明文。
- 成功自动返回可能让用户错过确认；保留约 600-900ms 的成功反馈，但顶栏状态必须先更新。
- 远程头像可能失败或携带外部请求；头像为可选增强，不得影响认证成功判定。

## 未决 UI 问题

- B 站扫码确认响应可稳定提供哪些账户展示字段（昵称、UID、头像）需在架构/API 契约阶段确认；缺失字段时使用“已登录账号”而非猜测。
- 应用窗口无法真正“关闭登录页”，本设计固定为返回来源路由或 `/download`，需在规格中写成唯一行为。
- `cancelled` 的上游状态码语义需由 Rust adapter 固定；UI 与 `expired` 分开呈现，但都只提供刷新入口。
