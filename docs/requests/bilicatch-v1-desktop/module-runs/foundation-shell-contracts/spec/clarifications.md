# 规格澄清：应用基础、壳层与共享契约

## Q1：是否手写项目骨架？

- 问题：仓库为空，bootstrap 方式未由 PRD 明确到命令级。
- 答案：框架要求绿地优先使用匹配 scaffold。
- 最终决策：使用官方 `create-tauri-app` Vue + TypeScript 模板，npm 作为包管理器。
- 影响区域：项目初始化、配置、目录结构、验收 AC-FND-01。

## Q2：Vite 是否必须锁定 6.x？

- 问题：官方 scaffold 的稳定依赖可能已高于 PRD 编写时的 Vite 6.x。
- 答案：PRD 的技术方向固定，但强制不兼容降级会损害可构建性。
- 最终决策：优先采用 scaffold 当前相互兼容的稳定版本；若 Vite 非 6.x，在 changelog 记录偏差和理由。
- 影响区域：package 依赖、构建验证。

## Q3：首模块是否实现完整业务页？

- 问题：应用壳需要路由目标，但各业务模块尚未进入自己的生命周期。
- 答案：顺序模块规则禁止提前跨模块实现。
- 最终决策：四个路由仅提供可辨识、无伪功能的占位页；后续模块按序替换内容。
- 影响区域：路由、页面文件、模块边界。

## Q4：主题和语言是否在本模块持久化？

- 问题：应用壳需要可切换基础，但持久化属于设置模块。
- 答案：当前模块只建立运行时状态与 provider。
- 最终决策：本模块可在内存中切换；tauri-plugin-store 持久化由 settings 模块实现。
- 影响区域：app store、设置占位、验收 AC-FND-05/06。

## Q5：应用图标缺失如何处理？

- 问题：PRD 要求多平台图标，但未提供品牌资源。
- 答案：不阻塞应用壳开发。
- 最终决策：保留 scaffold 图标或中性占位，系统发布模块再替换并验证完整资源。
- 影响区域：品牌区、Tauri bundle。

## Q6：当前 TypeScript 配置依据是什么？

- 问题：规格阶段仓库没有 tsconfig。
- 答案：不能猜测生成结果。
- 最终决策：执行阶段先 scaffold，再读取实际 tsconfig extends 链和最小相关声明闭包，记录结果后才编码。
- 影响区域：全部 TypeScript 文件、执行门禁、验收 AC-FND-11。
