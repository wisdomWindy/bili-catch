# 页面设计：下载任务管理

## 交付单元标识

`task-management`

## 页面目标

把 `/tasks` 从占位页升级为持续工作的任务控制台。用户进入页面后应先看见队列整体状态，再快速定位活动、完成或失败任务，并在不离开列表的情况下完成暂停、恢复、取消、重试、打开和清理。

## 目标用户与场景

- 连续添加多个分 P 的学习者：需要扫描文件名、进度、速度和剩余时间，及时暂停或恢复任务。
- 批量归档用户：需要过滤失败项、重试单项、清理已完成记录，并确认队列没有超过 100 项。
- 应用重启后的用户：需要明确看见恢复中的未完成任务，而不是误以为队列丢失。
- 紧凑桌面窗口：需要在有限宽度下保留状态、进度和当前合法操作。

## 布局结构

页面使用单一全宽工作区，不在壳层内容区内再包外层卡片：

```text
+------------------------------------------------------------------+
| Filter tabs + counts                 Pause all | Clear completed |
|------------------------------------------------------------------|
| Filename               Status    Progress   Speed / ETA   Actions |
| [media identity]       [badge]   [bar + %] [values]      [icons] |
|------------------------------------------------------------------|
| ...                                                              |
+------------------------------------------------------------------+
| Optional compact queue/error banner                              |
+------------------------------------------------------------------+
```

- 复用 AppShell、顶栏标题和 `content-container`；任务页启用现有最大可读宽度，不新建浮动 section。
- 工具条与列表表头在内容滚动区顶部连续排列；长队列滚动时表头可 sticky，壳层顶栏保持原有层级。
- 列表主体至少保留约 360px 可视高度；加载、空态和错误态使用相同占位高度，减少状态切换跳动。
- 每条任务是表格行/语义列表项，不是独立浮动卡片；行间使用细分隔线。

## 视觉层级

1. 活动进度：文件名、状态和进度是每行第一视觉层，下载中的进度条使用品牌色，处理阶段使用信息色。
2. 异常：失败状态使用危险色图标、文字和错误摘要，不只依赖颜色；失败任务在“失败”标签计数中可见。
3. 行操作：只显示当前状态合法的 1-2 个高频图标命令，危险操作与主操作保持间距。
4. 批量命令：位于筛选工具条右侧，只有存在适用任务时启用；不与页面标题争夺注意力。
5. 次要遥测：速度、剩余时间和总大小使用等宽数字特征与次文字颜色，便于纵向比较。

## 区块拆分

### 筛选与批量工具条

- 使用四项 tabs：全部、下载中、已完成、失败；每项显示当前数量，但计数为 0 时仍保留稳定宽度。
- “下载中”定义为活动集合：`queued`、`downloading`、`paused`、`processing`。这样暂停和媒体处理任务不会从用户当前工作视图中消失。
- 右侧提供“暂停全部”和“清除已完成”。暂停全部只作用于可暂停的 downloading；清除已完成只删除任务记录，不删除输出文件。
- 批量命令使用 Lucide 图标 + 短文本；禁用时提供 tooltip/可访问描述说明没有适用任务。
- 队列接近或达到 100 项时，在工具条下显示紧凑容量提示；达到上限为 warning，不遮挡现有任务操作。

### 任务表头与列

- `>=1100px` 使用六列：文件/媒体、状态、进度、速度、剩余/大小、操作。
- 文件列为弹性主列，最小 260px；状态 104px；进度 150px；速度 96px；剩余/大小 112px；操作 88-120px。
- 文件名单行省略，hover/focus tooltip 展示全名；次行显示下载类型与分 P 信息，不重复展示不可操作的原始 URL。
- 数值不可用时显示语义短横线；不能用 `0 B/s` 冒充暂停、排队或处理状态。

### 任务行

- 状态 badge 使用 6px 以内圆角并包含文字：排队中、下载中、已暂停、处理中、已完成、失败、已取消。
- downloading：进度条、百分比、实时速度、剩余时间、已下载/总大小；操作为暂停、取消。
- queued：进度为 0 或恢复值，速度/ETA 为短横线；操作为取消。
- paused：保留最后进度，速度/ETA 停止显示；操作为恢复、取消。
- processing：进度区域显示确定阶段文案或不确定进度动画；操作只保留取消（若后端阶段允许）。
- failed：保留失败时进度，文件次行显示一行可截断错误摘要；操作为重试、删除记录。
- completed：进度固定完成；显示最终大小；操作入口提供打开文件、打开所在目录、删除记录。
- cancelled：不作为四个顶层筛选的独立标签；保留在“全部”，只允许删除记录。
- 行操作优先熟悉的 Lucide 图标按钮，均带 tooltip 与 `aria-label`；“打开”存在两个相近命令时使用小菜单区分，避免并排三个以上图标。

### 空态、加载与错误

- 初始恢复任务时显示 5 行固定列宽 skeleton，筛选工具条仍可见但批量操作禁用。
- 全部为空：复用共享 EmptyState，主命令“前往下载中心”导航 `/download`。
- 某筛选为空：显示对应简短状态，如“暂无失败任务”，不提供营销式说明。
- 读取持久任务失败：列表区域展示 inline error 与重试；若已有内存任务，使用顶部 error banner 并保留可用列表。
- 单项操作失败：该行保持原状态或回滚 optimistic 状态，行内显示错误标识，同时触发全局错误通知。

### 确认与反馈

- 取消活动任务需要确认，文案明确会立即删除临时文件；确认按钮使用危险色。
- 删除记录对 failed/cancelled 可直接执行；completed 删除只移除记录、不删除输出文件，并在首次确认文案中明确。
- 清除已完成需要一次批量确认并展示数量。
- 暂停、恢复、重试成功依赖状态变化本身作为反馈，不额外堆叠成功通知；失败操作使用通知。

## 样式方向

- 延续全局系统字体、语义色与 4px 间距体系；表头/正文 12-14px，工具条控件高 36px，行最小高 68px。
- 页面背景、行背景和分隔线沿用 `--color-bg`、`--color-surface`、`--color-border`；不引入单色蓝/紫主题或渐变。
- 品牌粉只用于活动进度与明确主操作；成功、警告、危险、信息分别使用既有语义色。
- 进度条固定高度 6px、宽度不随百分比文本改变；状态 badge、操作按钮和计数具有稳定尺寸，事件更新不引起列跳动。
- 卡片只保留给共享 EmptyState 或真正的弹窗；任务列表本身为无框表面区。
- 所有文字 letter-spacing 为 0；文件名和长错误使用省略 + tooltip，不用视口宽度缩放字号。

## 交互骨架

1. 页面挂载 -> 请求持久化任务快照 -> 订阅 Rust 任务事件 -> 按 task id 合并最新合法状态。
2. 用户切换筛选 -> 仅改变前端派生视图，不重新请求或复制任务集合；键盘左右键可切换 tabs。
3. 用户触发行操作 -> 操作进入行级 busy，禁用该任务的重复命令 -> IPC 成功等待/应用权威事件，失败则解除 busy 并展示错误。
4. 暂停全部 -> 只对当前所有 downloading 发出批量命令，不受当前筛选限制；按钮 busy 时防止重复提交。
5. 清除已完成 -> 确认数量 -> 删除 completed 记录 -> 更新计数；输出文件保持不变。
6. 收到进度事件 -> 合并到对应 id；终止态事件后忽略更早序列或非法回退事件；不得因排序变化抢走键盘焦点。
7. 重启恢复中的任务先显示“恢复中”，恢复判定后进入 queued/paused/failed 等权威状态。

## 响应式行为

- `>=1100px`：完整六列，速度与剩余/大小分列；任务页使用壳层允许的宽内容模式。
- `860-1099px`：合并为四列“文件、状态、进度/遥测、操作”；速度、ETA、大小在进度条下方同一行显示。
- `<860px` 极窄容错：每项改为无浮动外框的两行 grid；第一行文件+状态，第二行进度+操作，速度/ETA/大小放在第三个紧凑 metadata 行。工具条允许两行，tabs 横向滚动但不压缩文字。
- 表头在极窄布局隐藏但保留每个值的可访问标签；操作区固定宽度，文件名缩短而不是覆盖按钮。
- 英文状态与命令按较长文本预留，无法放入图标按钮的完整名称通过 tooltip/aria-label 提供。

## 可访问性

- tabs 使用 `role=tablist/tab` 或组件库等价语义，当前项有 `aria-selected`；计数不单独进入冗余朗读。
- 进度使用 `progressbar` 语义及当前值；processing 的不确定状态使用 `aria-valuetext`。
- 任务更新通过节流的 `aria-live=polite` 汇总，不能每个下载 chunk 都触发朗读。
- 确认对话框将初始焦点放在非破坏性取消，关闭后归还触发按钮。
- 图标按钮具备 tooltip、`aria-label`、可见 focus ring 和至少 36x36px 点击区域。

## 设计风险

- 高频 Rust 进度事件可能导致整表重渲染和数值跳动；架构规格必须定义事件节流、按 id 局部合并与稳定排序。
- 状态操作矩阵较密集；必须由单一 action policy 派生，不能在多个行组件中散落条件判断。
- “处理中”是否可取消取决于后端阶段的可中断性；默认设计保留取消入口，但需由架构/规格绑定合法 transition。
- 打开文件/目录依赖系统插件与路径仍存在；操作失败必须可观察，不能静默。
- 持久化恢复期间若先收到实时事件，快照可能覆盖新状态；架构阶段必须定义版本/序列合并顺序。

## 开放 UI 问题

- PRD 没有定义默认排序。本设计采用“活动任务在前；各组内按创建时间倒序”，且实时进度不改变排序；作为规格默认口径。
- “下载中”筛选按活动集合解释，包含排队、下载、暂停和处理；该解释保留所有未完成任务的可发现性。
- `processing` 的取消能力由架构阶段按实际任务状态机确认；若无法安全中断，则该状态不显示取消。
- 删除 completed 只删除记录、不删除输出文件，沿用 requirement-map 的既定决策。
