# 页面设计：设置管理

## 交付单元标识

`settings`

## 页面目标

在现有 BiliCatch 工作台内提供安静、紧凑且可快速扫描的全局设置页。用户应能在一个连续页面中完成下载、外观、系统行为与版本信息配置；所有变更无需手动提交，并能清楚看到正在保存、已保存或保存失败的状态。

## 目标用户或场景

- 首次使用者确认媒体保存位置、临时文件位置和常用媒体默认值。
- 高频下载用户调整最大并发任务数与单任务连接数，并在拖动过程中看到精确数值。
- 用户切换主题或界面语言，希望当前界面立即响应且重启后保持。
- 桌面用户配置完成通知、关闭窗口行为和启动时自动检查更新。
- 用户查看当前版本、主动检查更新或打开开源许可页面。

## 布局结构

页面沿用 `AppShell` 的侧栏、56px 顶栏和内容滚动区。主体为一个连续设置表单，以分组标题、说明和水平分隔线组织，不使用页级浮动卡片、标签页或折叠面板。

## 视觉层级

1. 页面 H1“设置”与一句简短状态说明建立当前上下文；不使用营销式大标题。
2. “下载设置、外观设置、系统设置、关于”是二级扫描锚点，区组之间用留白和细分隔线区分。
3. 每行左侧标签为主信息，可选的一句说明使用次级文字；右侧控件保持统一起始线和稳定宽度。
4. 控件值是操作焦点；保存状态放在固定宽度尾列，避免“保存中/已保存/失败”切换引发布局跳动。
5. 错误使用危险色与图标共同表达；成功状态保持克制，短暂显示后回到静默状态。

## 区块拆分

### 页面标题与全局状态

- H1 与下载中心、任务列表页面同级，内容容器沿用现有最大宽度和 24/16px 页面内边距。
- 首次加载设置时，设置行保留稳定高度并显示轻量 skeleton；控件在数据就绪前禁用。
- 设置存储整体不可用时，在标题下显示紧凑 inline alert，并提供“重试”按钮；已成功载入的行不被错误遮挡。
- 页面不显示手动“保存”按钮，也不使用常驻“所有更改已保存”横幅。

### 下载设置

- **下载目录**：只读路径输入框加 `FolderOpen` 图标按钮；默认值显示为后端解析后的实际 `安装目录/BiliCatch` 路径。按钮 tooltip 为“选择下载目录”。
- **临时文件目录**：与下载目录同构；默认显示安装目录下 Temp 的实际路径。
- 路径过长时输入框单行省略，聚焦或 hover 可查看完整值；完整路径仍作为可访问名称提供。
- **最大并发任务数**：范围 `1-10`、步长 `1`、默认 `3`；滑块末端有固定宽度数值输出。
- **单任务连接数**：范围 `1-32`、步长 `1`、默认 `8`；结构与最大并发保持一致。
- **默认视频清晰度**：下拉选择，默认 `1080P`；选项契约由规格阶段固定，不用自由文本输入。
- **默认音频格式**：下拉选择，默认 `MP3`；选项与下载中心媒体格式契约共享。

### 外观设置

- **主题**：下拉选择“亮色、暗色、跟随系统”，默认“跟随系统”。选择后当前应用立即切换主题，再持久化新值。
- **语言**：下拉选择“简体中文、English”，默认值按持久设置或产品默认语言恢复。选择后当前页面、侧栏和顶栏立即更新。
- 两个控件使用枚举值而非自由输入；下拉宽度需容纳中英文最长选项，不随当前值改变。

### 系统设置

- **下载完成后通知**：开关，默认开启；标签点击与开关本体触发同一操作。
- **关闭窗口行为**：下拉选择“最小化到托盘、直接退出”，默认“最小化到托盘”。
- **自动检查更新**：开关，默认开启，仅控制启动时检查行为，不替代“关于”区的主动检查更新操作。

### 关于

- **当前版本**：只读文本，使用应用运行时版本，不允许用户编辑。
- **检查更新**：`RefreshCw` 图标加文本按钮；检查期间按钮保持原尺寸、禁用并显示 spinner，结果通过紧邻行的状态和非阻断通知呈现。
- **开源许可**：使用外链图标按钮或图标加短文本链接，打开系统浏览器；必须有清晰的可访问名称。
- 更新端点和许可地址由 `system-release` 模块提供；目标缺失或原生调用失败时保留当前页并显示本地化错误，不静默失败。

## 样式方向

- 复用现有工作台的 surface、text、border、brand、info、success、warning、danger token，不引入新的大面积主题色、渐变或装饰背景。
- 表单主体建议最大宽度 `880px`，左对齐内容区；每组为无边框全宽 section，仅组间使用分隔线。
- 桌面行采用稳定网格：`minmax(180px, 240px) minmax(280px, 1fr) 88px`。路径行的按钮位于控件内部尾端，状态列不挤压路径。
- 行高由控件与说明决定，基础控件高度至少 `36px`；圆角不超过 `8px`；字间距统一为 `0`。
- 滑块轨道、开关和 select 使用现有 Naive UI 主题覆盖及语义 token，明暗主题下均保持足够对比度。
- 不为每个设置项创建卡片，不在卡片内嵌套卡片，也不使用装饰图标代替字段标签。

## 交互骨架

1. 进入 `/settings` -> 读取版本化持久设置 -> 用默认值补齐缺失字段 -> 一次性呈现可操作表单。
2. 普通 select、switch 改变 -> 更新对应行的本地值 -> 显示“保存中” -> 持久化 -> 成功后短暂显示“已保存”。
3. 持久化失败 -> 当前行回退到最后一次确认值 -> 显示错误图标与短文案 -> 发送非阻断错误通知；其他行仍可操作。
4. 主题/语言改变 -> 先立即应用 UI -> 持久化；失败时同时回滚持久值和已应用的主题/语言，避免界面与存储不一致。
5. 拖动滑块 -> 只更新可见数值，不写存储；指针/触摸释放或键盘变更提交后持久化一次。失焦前仍有未提交键盘值时完成提交。
6. 点击路径按钮 -> 打开系统目录选择器；取消选择不改值、不显示错误；选中目录后先经边界校验，再回填并保存。
7. 同一行保存中再次变更 -> 以最新值为准串行或取消旧请求；旧请求完成不得覆盖新值或新状态。
8. 点击“检查更新” -> 进入 checking -> 分支为有更新、已是最新、失败；结果不导航离开当前页。
9. 点击“开源许可” -> 通过系统浏览器打开配置目标；应用内不嵌入远程网页。

## 状态规格

| 范围 | 状态 | 页面表现 | 可操作性 |
| --- | --- | --- | --- |
| 页面 | `loading` | 稳定行 skeleton | 设置控件禁用 |
| 页面 | `ready` | 显示持久值或补齐后的默认值 | 全部可操作 |
| 页面 | `load_error` | 标题下 inline alert 与重试 | 未知值控件禁用 |
| 单行 | `idle` | 不显示尾部文案 | 可操作 |
| 单行 | `dirty_preview` | 滑块数值实时变化 | 可继续调整 |
| 单行 | `saving` | spinner + “保存中” | 保持稳定尺寸，允许捕获最新变更 |
| 单行 | `saved` | 对勾 + “已保存”，短暂后淡出 | 可操作 |
| 单行 | `save_error` | 错误图标 + 短文案，值已回退 | 可重新修改 |
| 目录 | `picking` | 文件夹按钮显示 spinner | 仅该按钮禁用 |
| 更新 | `checking` | 按钮 spinner，结果区域清空旧消息 | 该按钮禁用 |
| 更新 | `available/latest/error` | 行内结果 + 对应非阻断通知 | 可再次检查 |

## 响应式行为

- `>= 900px`：使用三列设置行，标签/说明、控件、状态对齐；路径和滑块占满控件列。
- `760-899px`：标签列缩至约 `180px`，控件保持 `minmax(260px, 1fr)`，状态仍保留固定宽度。
- `< 760px`：每个设置行改为单列，标签在上、控件在下、状态紧随控件；section 不横向滚动。
- `< 520px`：沿用 60px 侧栏，路径输入与图标按钮使用 `minmax(0, 1fr) auto`；滑块与数值输出使用稳定两列，最长中英文标签允许换行。
- 任意宽度下，保存状态、错误文案和版本号不得覆盖相邻控件；不使用随视口宽度缩放的字号。

## 无障碍行为

- 每个控件都有程序化标签；说明和行级错误通过 `aria-describedby` 关联。
- switch 暴露真实开关状态，select 保持键盘导航；图标按钮必须有 tooltip 与 `aria-label`。
- 滑块提供 `min`、`max`、`step`、当前值和可理解的 `aria-valuetext`，视觉数值输出不作为重复 live region。
- 行级保存结果使用 `aria-live="polite"`，仅在状态转换时播报，不因滑块每个刻度连续播报。
- 错误不只依赖颜色；焦点环沿用全局 token。目录对话框关闭后焦点回到原触发按钮。
- 主题切换保持焦点位置；语言切换后当前控件仍可识别，不自动滚动页面。

## 设计风险

- 即时保存若缺少每字段的请求归属，快速连续操作可能出现旧响应覆盖新值；架构必须提供按字段排序或 latest-wins 保护。
- 主题/语言涉及即时副作用，存储失败若只回退数据而不回退 UI 会产生双状态；必须共享同一事务结果。
- 路径字符串跨平台差异大；UI 只展示后端返回的规范路径，不自行拼接 `~`、盘符或分隔符。
- 大量“已保存”提示会制造视觉和辅助技术噪声；成功反馈短暂且局部，错误才持久保留到下一次操作。
- 更新与许可依赖后续系统发布配置；设置页只定义稳定交互状态，不在本模块硬编码发布地址。

## 未决 UI 问题

- 默认视频清晰度和默认音频格式的完整选项集需在规格阶段与下载中心共享契约对齐；页面设计固定控件形态、默认值与异常表现，不复制一份易漂移的选项常量。
- 更新可用后的安装确认界面属于 `system-release` 模块；本页当前只承诺检查动作与“有更新/已最新/失败”结果容器。
- 开源许可的最终目标地址由 `system-release` 配置；缺失配置统一走行级错误，不提供假链接。
