## 业务意图
建立后续模块可安全扩展的可运行桌面应用骨架和稳定共享边界。

## 用户可见范围
- 默认进入下载中心。
- 可从侧栏进入下载中心、任务列表和设置。
- 顶部可返回、查看登录状态并进入设置。
- 基础主题、中文默认文案和英文切换结构可用。

## 表单、表格、展示与交互
- 应用壳由固定导航区、顶部栏和路由内容区组成。
- 当前路由有明确选中态；不可用后端能力通过统一错误/空状态表达。
- 本模块不实现各业务页面的完整表单或表格。

## 工作流与状态规则
- Router 使用 Hash history。
- Pinia 是跨页状态入口。
- IPC 对外只暴露稳定 DTO 与 `AppError`，页面不消费外部原始 JSON。

## 依赖与受影响邻居
无前置；被其余全部模块依赖。

## 页面设计路由判定
需要：必须确定全局壳层、导航密度、窗口适配和视觉语言。

## 架构设计路由判定
需要：必须决定 scaffold、目录、tsconfig、共享类型、IPC adapter 与 Rust 分层边界。

## 下游规格义务
- 明确 scaffold 选择并采用合适官方模板。
- 定义路由、导航、布局、主题 token、i18n、错误 DTO 和 mock/real IPC 切换。
- 定义最小可测试页面占位与工程门禁。

## 开放问题
无业务阻塞；真实系统能力在后续模块接入。
