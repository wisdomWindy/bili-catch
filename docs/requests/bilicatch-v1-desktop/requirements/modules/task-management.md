# 模块：下载任务管理

## 模块标识
`task-management`

## 来源快照

- `/tasks` 包含全部、下载中、已完成、失败筛选。
- 每项展示文件名、状态、进度、速度、剩余时间、大小与操作。
- 下载中：暂停/取消；暂停：恢复/取消；失败：重试/删除；完成：打开文件或所在目录/删除记录。
- 支持暂停全部、清除已完成；进度由 Rust `emit` 推送；重启恢复未完成任务。
- 队列最多 100，默认并发 3；取消立即清理临时文件。

## Markdown 归一化快照
原文任务表与流程保留为“筛选模型 + 行展示字段 + 状态操作矩阵 + 队列状态机 + 持久化恢复规则”。

## 来源追踪
`biliCatch_PRD.md` 模块四（约 340-422 行）、3.2、5.1。

## 业务意图
让用户观察并控制所有下载，且在并发、失败与重启下保持一致状态。

## 用户可见范围
任务列表、筛选、进度、批量操作、状态相关行操作、空态与失败反馈。

## 表单、表格、展示与交互
筛选标签；任务行字段；暂停、恢复、取消、重试、打开、删除；暂停全部和清除完成。

## 工作流与状态规则
queued -> downloading -> processing -> completed；downloading 可 paused/cancelled/failed；paused 可 downloading/cancelled；failed 可重试回 queued。事件按 task id 合并，终止状态不得被迟到事件回退。

## 依赖与受影响邻居
依赖基础契约和任务创建输入；被音频、视频、托盘、通知消费。

## 页面设计路由判定
需要：高密度列表、状态徽标、稳定列宽、上下文操作与空/错状态。

## 架构设计路由判定
需要：任务状态机、调度器、事件、持久化和并发控制。

## 下游规格义务
保留 100 上限、全部字段和操作矩阵、批量操作、恢复、临时文件清理、事件一致性。

## 开放问题
删除默认只移除记录，不删除已输出文件。
