# 模块：登录与认证

## 模块标识
`authentication`

## 来源快照

- `/login` 生成并显示 B 站二维码，Rust 轮询状态。
- 状态：未扫码、已扫码待确认、已确认、已过期、已取消。
- 约 180 秒过期并停止轮询；过期提供刷新。
- 成功后获取 Cookie、加密存储并刷新登录状态；启动恢复；退出清除。
- 每次解析前检查 Cookie 有效性；匿名仍可使用基础下载。

## Markdown 归一化快照
原流程图归一为：idle -> requesting -> waiting_scan -> waiting_confirm -> authenticated，另有 expired/cancelled/error；原提示和 180 秒规则不变。

## 来源追踪
`biliCatch_PRD.md` 1.4、3.2、模块五（约 423-478 行）、5.4。

## 业务意图
安全获得本机用户授权的 B 站会话并提供可恢复认证上下文。

## 用户可见范围
二维码、倒计时/状态提示、刷新、已登录用户状态、退出登录和登录能力说明。

## 表单、表格、展示与交互
二维码展示；扫码状态；刷新按钮；退出按钮；顶栏登录入口状态。

## 工作流与状态规则
页面进入按需生成二维码并轮询；卸载、过期、取消后停止；成功持久化；解析前校验失效则降级匿名并提示重新登录。

## 依赖与受影响邻居
依赖基础 IPC/错误/存储边界；影响解析可用流、FLAC/HiRes 和顶栏状态。

## 页面设计路由判定
需要：二维码各状态、已登录与匿名状态都需明确布局。

## 架构设计路由判定
需要：轮询生命周期、Cookie 加密端口、会话校验和敏感日志边界。

## 下游规格义务
保留五态、180 秒、停止/刷新、加密、恢复、退出、解析前校验和匿名可用。

## 开放问题
凭据存储的具体平台实现由架构阶段决定，不得硬编码明文密钥。
