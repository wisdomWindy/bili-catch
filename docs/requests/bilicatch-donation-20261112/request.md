# 请求：添加打赏功能

- 请求标识：`bilicatch-donation-20261112`
- 来源：用户于 2026-11-12 的直接变更指令及两张收款码图片
- 业务摘要：在 BiliCatch 中提供可发现的打赏入口，并展示用户提供的支付宝与微信收款码。
- 目标：用户能从设置页“关于”区域打开打赏界面，在桌面端与窄窗口中清晰查看两张收款码并关闭界面。
- 初始完成信号：关于区域出现“打赏”入口；入口可打开包含两张原始收款码的界面；界面可通过显式关闭、遮罩或 Esc 关闭；键盘焦点可达且关闭后回到触发按钮；中英文、明暗主题与窄窗口均可用。
- 触发条件：用户进入设置页并操作“关于”区域中的打赏入口。
- 初始上下文：用户直接指令、两张图片附件、`AboutSettings.vue`、设置页样式、国际化字典、现有 `NModal` 对话框模式与相关测试。
- 人工交接点：完成实现、自动化测试、构建、桌面/窄窗口视觉验证与审查后交付。
- 受影响区域：设置页“关于”区域、设置国际化文案、设置页局部样式、静态收款码资源与组件测试。
- 参与模块：`src/features/settings`、`src/locales`、`public` 静态资源；不涉及后端、IPC、路由、支付状态或交易确认。
- Greenfield scaffold sensitivity：不适用；本请求是在现有 Vue/Tauri 应用中增加局部功能。
- PRD-only 阶段：不需要 `requirement-analysis` / `requirement-splitting`；来源是范围稳定的单功能直接变更，使用请求级交付单元。

## 用户意图合同

- stated request：`添加打赏功能，上传的图片为收款码`。
- practical goal：让愿意支持项目的用户能方便、安全地找到并扫码使用用户提供的收款码。
- success criteria：入口可发现、两张收款码保持原始可扫描内容、弹层在支持的窗口尺寸与主题下完整可用。
- forbidden interpretations：生成或重绘二维码、修改收款信息、增加支付金额选择、支付结果确认、联网支付接口、交易记录或其他未请求的支付流程。
- acceptable approaches：在现有“关于”区域增加一个图标按钮，并用现有对话框能力展示两张本地图片。

## 前置确认结论

- 用户已明确提供两张图片作为收款码，图片内容分别标识支付宝和微信支付，可作为展示资产使用。
- 本次不需要用户补充支付接口、金额规则或交易状态，因为范围仅为展示收款码供扫码打赏。
- 界面安置在“关于”区域属于现有信息架构约束下的最窄实现，不新增导航或业务模块。
