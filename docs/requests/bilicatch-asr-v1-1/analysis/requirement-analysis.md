# 音频转文本 V1.1 需求分析

## 分析摘要

本请求交付一个可实际运行的本地 ASR 子系统，而非仅提供页面或 IPC 占位。核心闭环是“选择媒体 -> 确认模型 -> 排队 -> FFmpeg 预处理 -> 本地推理 -> 结果预览/编辑 -> 多格式保存”，并以模型管理、任务页、设置、下载后自动转写和系统通知作为同一交付单元内的必要支撑。

现有下载任务、设置和 FFmpeg 基础设施可复用，但转写具有不同状态、进度维度、结果数据和资源调度规则，不能把它伪装成下载任务。需求应保持一个业务交付单元，在代码和数据上建立独立转写领域，通过明确适配边界接入既有模块。

## 资料来源与阅读口径

| 来源 | 用途 | 优先级/口径 |
| --- | --- | --- |
| `biliCatch_PRD.md` 模块八及跨模块补充 | 产品行为、字段、状态、错误、性能和分发约束 | 业务语义最高优先级 |
| 用户 2026-10-10 方案批准 | 采用独立 V1.1 请求、sidecar、独立领域并集成现有模块 | 作为已确认设计方向 |
| 现有 `src/` 与 `src-tauri/` | 判断可复用能力、数据归属和回归边界 | 不能反向削弱 PRD |
| 现有 `docs/requests/bilicatch-v1-desktop/` | 理解历史模块契约和当前发布阻塞 | 只作基线，不复制结论 |
| `whisper.cpp` 官方发布与模型说明 | sidecar、CLI、模型文件的外部事实 | 以实现时固定版本和模型清单为准 |

## 已确认范围

1. 新增 `/transcribe` 页面、侧栏入口和任务/本地文件入口。
2. 支持 PRD 列出的 11 种音视频扩展名及已完成下载任务来源。
3. 支持 Tiny、Base、Small、Medium、Large-v3 模型的下载、校验、删除和默认切换。
4. 使用 FFmpeg 生成 16kHz 单声道 16-bit PCM WAV，使用 `whisper.cpp` sidecar 在本地推理。
5. 保存规范化分段结果，并导出 TXT、SRT、VTT、JSON、Markdown。
6. 支持结果预览、文本级编辑、复制、重新转写、缓存复用和打开目录。
7. 支持转写排队、取消、失败重试、进度事件、系统通知和任务页统一展示。
8. 支持设置页全部转写字段、下载后自动转写和平台字幕优先回退。
9. 增加 E011-E017 错误合同、sidecar 打包配置和模型目录生命周期。
10. 提供中英文 UI 文案及对主要状态、边界和合同的自动化测试。

## 非目标

- 实时录音转写。
- 说话人分离、字幕翻译和完整时间轴编辑器。
- 云端 ASR 或上传音频/文本。
- 为 ASR 顺带重构全部下载任务持久化结构。
- 将 ASR 模型内嵌安装包。
- 在当前 Windows 工作区声称完成 macOS/Linux 实机烟测或签名发布。
- 以“标点恢复”名义引入新的网络服务或未在 PRD 中定义的大模型。

## 已确认口径与不变量

- 音频和转写文本不上传；唯一网络行为是用户触发的模型下载及可选平台字幕读取。
- 默认模型 Base、默认语言自动检测、默认输出 SRT、默认转写并发 1。
- SRT/VTT/JSON 始终含时间戳；TXT 默认不含；Markdown 按用户设置决定。
- 模型下载必须通过 SHA-256 校验后才标记已安装。
- 转写任务状态独立于下载状态；任务页统一展示不等于共享同一个后端实体。
- 转写优先级低于下载，不能通过占满 CPU/槽位使下载执行器失去进展。
- 完成、失败、取消均要清理临时 PCM；不删除用户源文件或已有下载输出。
- 重新转写必须绕过缓存；普通相同请求允许复用缓存。
- 删除正在使用的模型前必须确认，并在仍被占用时拒绝删除。
- 用户批准 `whisper.cpp` sidecar 路径；本请求不再比较 `whisper-rs` 作为等价默认方案。

## 系统职责与边界

| 边界 | 责任 |
| --- | --- |
| Vue 页面/组件 | 收集参数、呈现状态、发起命令、编辑展示结果；不执行文件、模型或推理 I/O |
| Pinia 转写状态 | 管理页面会话、模型/任务/结果快照及事件合并；不定义后端状态转移 |
| Tauri IPC | 保存 Rust 字段语义并将稳定错误合同传给前端 |
| Rust 转写服务 | 校验、排队、状态机、缓存、结果编排、取消和重试 |
| FFmpeg adapter | 媒体探测、音轨抽取、重采样和 PCM 临时文件生命周期 |
| `Transcriber` port / whisper adapter | sidecar 调用、输出解析、推理取消和能力报告 |
| 模型仓储 | 清单、下载、原子落盘、SHA-256、占用保护和删除 |
| 下载任务模块 | 提供完成输出和自动转写触发；不拥有转写内部状态 |
| 设置模块 | 持久化 PRD 字段与校验范围；不直接启动转写 |
| B 站字幕 adapter | 查询/下载可用 CC 字幕并转为规范化分段；失败时允许回退本地 ASR |
| 发布环境 | 提供各平台 sidecar 二进制、签名和实机烟测证据 |

## 来源支持的行为清单

### 页面表单与操作

- 来源选择：已完成任务下拉、本地文件选择、单文件拖拽。
- 文件信息：名称、时长、大小、格式。
- 参数：模型、语言、输出格式、时间戳、标点、自动复制、保存目录。
- 运行操作：开始、取消、重新转写。
- 结果操作：文本编辑、复制全文、复制带时间戳、导出、打开目录。
- 模型操作：下载、校验、删除、默认切换、失败重试。

### 任务与状态

- 状态：等待中、转写中、后处理、完成、取消、错误。
- 进度：阶段、0-100、已处理/总时长、实时倍率、ETA、消息。
- 失败：E011-E017；错误任务可重试。
- 页面跳转：任务转写操作带 `taskId`；通知可唤起并定位转写页或任务页。

### 设置与默认值

转写设置包含 11 项：默认模型、默认语言、默认输出格式、时间戳、标点、平台字幕优先、自动转写、并发数、模型目录、GPU、模型下载源。即时保存；下载源仅影响后续下载。

## 面向开发者的行为细化

### 输入与校验

- 文件扩展名按大小写不敏感处理；选择后还必须确认文件存在且为普通文件。
- 页面只接受一个源文件。拖入多个文件时拒绝并提示，不隐式挑选第一个。
- 任务来源必须有非空 `outputPath` 且文件仍存在；失效任务项展示不可用原因。
- 开始按钮在无文件、元信息失败、模型未安装、正在提交时禁用。
- 保存目录输入去除首尾空白；归一化后为空视为无效，不进入创建成功路径。
- 模型下载源去除首尾空白；空值代表官方源；非空值必须为 HTTPS 基础 URL。

### 状态与并发

- 创建命令成功以返回持久化任务为准，不能以“invoke 未抛错”替代成功合同。
- 取消是幂等命令；终态任务重复取消返回当前任务，不制造第二个状态变化。
- 取消期间 UI 显示处理中，收到终态事件或查询确认后恢复操作。
- 进度事件按任务 revision/sequence 合并，过期事件不得覆盖更新快照。
- 设置并发数只影响后续调度，不强杀已经运行的任务。

### 模型管理

- 模型下载写入 `.part` 文件；取消/失败删除 `.part`，成功校验后 rename。
- 已存在但摘要不匹配的模型标记损坏，不作为可用模型。
- 模型目录变更不搬迁旧模型；新目录重新扫描，旧目录文件由用户自行管理。
- 自定义镜像只替换清单定义的基础地址，不允许任意文件名或路径穿越。

### 结果与导出

- 后端持有规范化分段：开始毫秒、结束毫秒、文本、语言；各格式由该结构生成。
- 文本编辑只修改段文本，不修改时间边界。
- 编辑内容在导出前去除每段首尾空白；空段可保留时间边界但不产生纯文本内容。
- 输出冲突通过顺序后缀解决，不覆盖现有文件。
- 自动复制失败不把已完成转写降级为失败，仅产生可见的前端操作错误。

## 隐含需求与隐藏假设

| 来源线索 | 隐含问题 | 当前口径 | 影响与承接 |
| --- | --- | --- | --- |
| 支持任务重试与缓存 | 任务与结果需跨页面/重启可恢复 | 已确认 | Rust 持久化任务和结果索引；规格定义 schema |
| 任务页统一展示 | 下载/转写状态字段不一致 | 已确认独立实体、统一展示投影 | 任务页 adapter 负责 UI union，不污染下载实体 |
| 删除使用中模型需确认 | 需要模型占用追踪 | 已确认 | 调度器维护 active model usage；删除命令二次校验 |
| 平台字幕优先 | 未提供 B 站字幕接口合同 | 外部接口待补 | `SubtitleProvider` 隔离；失败/无字幕回退 ASR |
| 标点恢复开关 | Whisper 自带标点，无独立算法 | 非阻塞假设 | 仅本地轻量后处理；不承诺额外模型质量 |
| GPU 自动/开/关 | sidecar 构建能力不同 | 外部能力待补 | capability 探测；开启但不支持时显式失败或提示降级 |
| 性能目标 | 硬件、音频和构建配置未固定 | 非阻塞 | 记录可复现 benchmark 环境，不作为通用单测断言 |
| 多平台分发 | 当前仅有 Windows 工作区证据 | 外部发布待补 | 编写跨平台定位契约，实机烟测由各平台环境完成 |

## 工作流与依赖判断

1. 模型管理和设置合同必须先稳定，页面才能准确判断可运行条件。
2. 转写服务依赖 FFmpeg adapter、模型仓储和 `Transcriber`，但三者均应可替换为测试替身。
3. 任务页集成依赖稳定的 `TranscribeTask` 展示投影；不应先改写下载任务状态机。
4. 自动转写依赖下载完成事件及输出路径，在主转写链路稳定后接入。
5. 平台字幕 adapter 是主链路前置分支，不得使无字幕或接口失败阻断本地 ASR 回退。
6. sidecar 打包和真实烟测必须在逻辑、命令参数和取消清理通过自动化测试后进行。

## 歧义与澄清登记

| 项目 | 为什么影响开发 | 分级 | 处理口径 |
| --- | --- | --- | --- |
| 官方模型未直接提供 PRD 指定的 SHA-256 清单 | 影响安装判定和供应链校验 | 外部接口待补 | 实施时下载固定模型版本并生成/复核应用 manifest，评审记录来源 |
| CC 字幕接口字段/鉴权 | 影响平台字幕优先分支 | 外部接口待补 | adapter + 回退；不阻塞本地 ASR |
| GPU sidecar 构建矩阵 | 影响“开启”的实际含义 | 外部接口待补 | capability 明示；CPU sidecar 是最低可交付基线 |
| 标点关闭的精确算法 | 影响输出文本形态 | 非阻塞 | 采用可逆的本地轻量规则；不下载额外模型 |
| 缓存文件指纹算法 PRD 未指定 | 影响同名文件误复用 | 非阻塞 | 使用规范化路径、大小和修改时间组成稳定指纹；重新转写可绕过 |

没有会改变核心流程、数据模型或权限边界的未决业务阻塞。

## 风险与约束评估

| 风险 | 触发条件 | 影响 | 后续保护 |
| --- | --- | --- | --- |
| 模型体积大且下载中断 | Medium/Large 或网络不稳定 | 模型管理、磁盘空间 | 流式写入、进度、`.part` 清理、原子落盘、重试 |
| sidecar CLI 版本漂移 | 更新 whisper.cpp | 推理参数和 JSON 解析 | 固定版本、adapter 契约测试、样例输出 fixture |
| 长音频资源占用 | 小内存设备或并发 3 | 下载吞吐和应用稳定性 | 分段、信号对齐、低优先级、并发限制、清理 |
| 统一任务页类型膨胀 | 直接扩展 DownloadTask | 下载回归 | 独立实体 + 展示 adapter + 下载回归测试 |
| 设置 schema 扩展 | 老用户已有 schema v1 | 启动加载失败 | 向后兼容默认填充和迁移测试 |
| 取消竞态 | FFmpeg/whisper/保存边界取消 | 残留文件、错误终态 | 单一取消 token、终态幂等、清理守卫 |
| 用户文本编辑与缓存冲突 | 修改后重新进入页面 | 结果丢失/旧结果覆盖 | 区分原始结果和可编辑保存版本，revision 校验 |
| 跨平台二进制不齐 | 非 Windows 打包 | 发布阻塞 | 平台清单和 CI gate；不伪造实机通过结论 |

## 阻塞项分类与处理口径

- 业务阻塞：无。
- 外部接口待补：B 站 CC 字幕合同、固定 whisper sidecar 的各平台二进制和签名、模型 SHA-256 manifest、GPU 构建能力矩阵。
- 非阻塞：标点关闭规则、缓存指纹细节、性能 benchmark 硬件基线。

所有外部接口待补项都有 adapter/config/发布门禁边界，允许继续进行规格和实现；真实发布结论必须诚实保留平台限制。

## 减少二次确认的开发提示

- 不再重新讨论 sidecar 与 `whisper-rs`；sidecar 已批准。
- 不把转写任务塞进 `DownloadTask`；统一仅发生在展示投影。
- 不以未安装模型时自动静默下载替代明确模型管理流程。
- 不覆盖现有输出文件，不删除用户源文件。
- 不因平台字幕接口失败而跳过本地 ASR 回退。
- 不把自动复制、打开目录等后置操作失败提升为推理失败。
- 外部二进制/模型摘要必须以固定 manifest 和证据承接，不能运行时相信任意远程元数据。

## 拆分策略

下游保留一个 `audio-transcription` 模块。拆分依据是完整业务闭环而非技术层：页面、模型、队列、结果、任务展示、设置和下载触发之间存在强验收耦合；任何再拆分都会产生用户无法完成转写或无法管理模型的中间版本。

模块内部可在计划阶段按合同、服务、基础设施、页面、集成和验证分任务，但这些不是独立产品模块。

## 下游阶段信号

- 需要 `page-design`：新增 `/transcribe` 页面、模型管理弹窗、任务页转写展示和设置分组。
- 需要 `architecture-design`：新增跨前后端领域、sidecar adapter、模型仓储、队列状态机、任务展示投影和多处集成。
- `requirement-splitting` 必须保留一个交付单元及完整 source trace。
- `spec` 必须定义完整字段、状态、IPC、持久化、失败、清理、缓存和跨模块联动合同。
