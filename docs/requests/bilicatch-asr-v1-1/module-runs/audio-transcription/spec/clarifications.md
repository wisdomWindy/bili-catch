# `audio-transcription` 澄清与决定

## Q1：使用 `whisper-rs` 还是 `whisper.cpp` sidecar？

- 回答：使用固定版本的 `whisper.cpp` sidecar。
- 最终决定：`Transcriber` trait 隔离 sidecar，CPU 构建是最低基线；不在本请求采用进程内绑定。
- 影响：架构、打包、取消、跨平台和真实 smoke。

## Q2：转写任务是否直接扩展现有 `DownloadTask`？

- 回答：否。
- 最终决定：Rust 中为独立实体和 store；任务页通过 TypeScript discriminated union 的展示 adapter 联合呈现。
- 影响：任务合同、状态机、持久化和回归范围。

## Q3：模型未安装时是否自动下载？

- 回答：否。
- 最终决定：显示 E011 并引导模型管理；自动转写也不静默下载模型。
- 影响：首次使用、自动转写和网络行为透明度。

## Q4：平台字幕接口未固定是否阻塞主链路？

- 回答：不阻塞。
- 最终决定：通过 `SubtitleProvider` adapter；Unavailable/Failed 都回退本地 ASR，fixture 到位后固定 raw DTO。
- 影响：下载任务来源的优化分支，不影响本地文件转写。

## Q5：PRD 要求 SHA-256，而官方模型清单未直接提供时如何处理？

- 回答：应用维护版本化 manifest。
- 最终决定：固定资产 URL/字节数，下载后生成并由独立证据复核 SHA-256；运行时只信任随应用发布的 manifest。
- 影响：模型供应链、测试和发布审核。

## Q6：标点恢复是否引入额外模型？

- 回答：否。
- 最终决定：默认保留 Whisper 标点；关闭时使用固定的本地轻量规则，不访问网络、不下载额外模型。
- 影响：后处理和纯函数测试。

## Q7：缓存键是否包含输出格式？

- 回答：识别缓存不包含输出格式。
- 最终决定：路径/大小/mtime/模型/语言/标点决定识别缓存；格式和时间戳只决定导出。该口径满足 PRD 的复用要求并避免重复推理。
- 影响：缓存、重新转写和导出。

## Q8：应用退出后是否断点恢复 sidecar 推理？

- 回答：不从中点恢复。
- 最终决定：非终态任务在启动后回到 Pending，清理旧 workspace 并从头重跑；下载模型可按 HTTP 能力后续扩展断点，本版不承诺。
- 影响：恢复语义和临时文件。

## Q9：GPU“开启”但 sidecar 不支持时怎么办？

- 回答：不能静默声称已使用 GPU。
- 最终决定：capability 探测；enabled 不支持时返回 E014/GPU_UNAVAILABLE，auto 可回退 CPU 并在任务诊断中记录。
- 影响：设置语义和发布构建矩阵。

## Q10：大结果是否必须引入虚拟列表？

- 回答：不是产品硬要求。
- 最终决定：先实现稳定滚动分段列表；以实现期基准确定是否需要轻量虚拟化，不能引入重型编辑器或改变编辑合同。
- 影响：前端性能，不影响领域/API。
