# 音频转文本 V1.1 需求拆分总览

## 请求摘要

将 `biliCatch_PRD.md` 新增模块八及其跨模块补充规范化为一个可独立完成设计、规格、计划、实现、验证和评审的交付单元。

## 需求分析承接

- 范围固定为完整本地 ASR 闭环，不接受仅 UI、仅 IPC 或模拟推理交付。
- 非目标固定为实时录音、说话人分离、翻译、完整时间轴编辑器和云端上传。
- 转写任务保持独立后端实体，通过展示投影进入现有任务页。
- `whisper.cpp` sidecar、FFmpeg 预处理、本地模型目录和 SHA-256 校验为已批准约束。
- B 站 CC 字幕字段、非 Windows 二进制和 GPU 构建矩阵作为外部 adapter/发布依赖，不阻塞本地 ASR 主链路规格。
- 页面、模型、队列、结果、任务、设置和下载联动共同构成一个验收闭环，不拆成可独立上线的多个模块。

## 拆分原则

1. 以用户可完成的业务闭环为模块边界，不按 Vue/Rust/文件层机械拆分。
2. 保留 PRD 的字段、交互、状态、错误、IPC、分发和性能约束。
3. 跨模块改动仅纳入完成 ASR 闭环所需的最小范围。
4. 外部不稳定接口必须通过 adapter 或 manifest 隔离，不把远程字段扩散到页面和核心状态机。

## 模块依赖与顺序说明

`audio-transcription` 消费已经存在的应用壳、IPC 错误、设置持久化、下载任务完成输出、FFmpeg sidecar、系统通知和文件对话框能力。它不能依赖尚未完成的旧 `bilicatch-v1-desktop/system-release` 发布凭据才能开发；真实多平台签名和发布烟测作为本模块发布交接项处理。

本请求只有一个模块，因此不存在模块间并行或后续模块晋升。模块必须依次完成：

`page-design -> architecture-design -> spec -> plan -> execute -> verify -> review`

## 模块执行序列

1. 当前模块：`audio-transcription`。
2. 首个阶段：`page-design`。
3. `page-design` 完成后进入 `architecture-design`。
4. 在规格和计划分别获得用户审批前不得编码。
5. 只有评审无阻断后才将请求置为完成。

## Spec 传递清单

### 来源与文件

- 支持 6 种音频、5 种视频格式、已完成任务、本地文件选择和拖拽。
- 单文件输入；无效、丢失、多文件拖入均有明确失败行为。

### 页面字段

- 文件信息、模型、语言、格式、时间戳、标点、自动复制、保存目录。
- 开始、取消、重新转写、复制、导出、打开目录。
- 模型下载、校验、删除、默认切换和进度。

### 状态和流程

- `pending -> transcribing -> processing -> completed`，支持 `cancelled`、`error`、重试。
- 进度包含阶段、百分比、处理/总秒数、速度、ETA 和消息。
- 完成/失败/取消均清理临时 PCM；取消幂等。
- 下载任务优先，转写并发 1-3。

### 结果和缓存

- 规范化分段、五种导出、时间戳规则、命名冲突后缀。
- 文本级编辑，不编辑时间轴。
- 同文件/模型/语言/输出格式缓存复用；重新转写绕过。

### 设置

- 11 项转写设置、默认值、范围、即时保存和下载源生效时机。

### 合同与失败

- 保留 PRD 建议 IPC 名称及两个进度事件。
- E011-E017 的场景和用户提示必须稳定。
- 模型 SHA-256、原子落盘、占用保护和自定义 HTTPS 镜像约束。

### 分发和质量

- whisper sidecar 目标三元组定位、模型不随包、升级保留模型。
- 中英文文案、可访问性、真实 Windows 烟测和跨平台发布交接。

## 开放问题与未决歧义

- B 站 CC 字幕具体字段和鉴权由 adapter fixture 在实现前固定。
- 各平台 whisper sidecar 构建产物和 GPU 能力由发布环境提供；CPU 版本为最低基线。
- 应用模型 manifest 的 SHA-256 在固定下载资产后生成并作为审核证据。
- 标点关闭使用轻量本地规则，不引入额外模型；精确字符规则在 spec 固定。
