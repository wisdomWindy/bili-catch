# PRD 结构化快照：音频转文本（ASR）

## 来源摘要

- 权威来源：`biliCatch_PRD.md`
- 核心章节：模块八 8.1-8.13
- 关联章节：1.1-1.3、2.2-2.4、3、模块二、模块四、模块六、模块七、5.1、5.5、6.1、6.2、7.1、7.2
- 版本定位：PRD 建议 V1.1；本请求按独立 V1.1 子系统实施。
- 隐私原则：默认完全本地处理，音频与识别文本不上传。

## 关键业务目标

1. 对本地音频、视频及已完成下载任务执行本地 ASR。
2. 支持自动语言检测、时间戳、标点恢复和多格式导出。
3. 支持模型按需下载、删除、校验与默认模型切换，模型不内嵌安装包。
4. 支持下载完成后自动转写，并在任务页统一观察和控制转写任务。
5. 长音频分段处理，转写默认不抢占下载任务资源。

## 显式行为约束

### 输入格式与来源

| 来源 | 支持格式或条件 | 行为 |
| --- | --- | --- |
| 音频文件 | MP3、M4A、AAC、FLAC、WAV、OGG | 读取音频轨道后预处理 |
| 视频文件 | MP4、MKV、FLV、MOV、WebM | 通过 FFmpeg 抽取音频轨道 |
| 已完成任务 | 必须已有可用输出文件 | 从任务页或转写页选择并带入路径、标题、时长 |
| 本地文件 | 文件选择器或拖拽 | 校验文件存在性与扩展名后读取元信息 |
| 下载联动 | 音频或包含音频的下载任务 | 可在下载完成后自动创建转写任务 |

### 输出格式

| 格式 | 时间戳规则 | 主要用途 |
| --- | --- | --- |
| TXT | 默认无 | 纯文本与笔记 |
| SRT | 必须有 | 播放器字幕 |
| VTT | 必须有 | Web 字幕 |
| JSON | 必须有 | 包含分段起止时间、文本和语言的结构化数据 |
| Markdown | 可选 | 笔记和知识库导入 |

### 模型目录

| 模型 | 参考体积 | PRD 定位 |
| --- | --- | --- |
| Tiny | 约 75MB | 快速预览 |
| Base | 约 142MB | 默认模型 |
| Small | 约 466MB | 中文推荐 |
| Medium | 约 1.5GB | 高质量归档 |
| Large-v3 | 约 3GB | 高精度/GPU 场景 |

模型以 GGML 文件按需下载，存放于模型目录。下载必须写入临时文件、完成摘要校验后原子落盘；删除正在使用的模型前必须二次确认。

### 模型管理弹窗

- 展示 Tiny、Base、Small、Medium、Large-v3 的安装状态、体积、推荐说明和当前默认标识。
- 支持下载、下载进度、失败重试、完整性校验、删除和设为默认。
- 下载中的模型不可重复下载；使用中的模型不可直接删除。
- 下载或校验失败必须保留明确错误并清理不完整临时文件。

### 任务页集成

- 转写任务复用任务列表页展示，增加任务类型标识和转写筛选条件。
- 转写任务状态：`pending -> transcribing -> processing -> completed`，并支持 `cancelled`、`error` 和重试。
- 下载任务完成卡片增加“转写”操作，跳转 `/transcribe?taskId=<id>`。
- 转写任务展示阶段、进度、已处理时长、总时长、速度、ETA、错误和可用操作。

### 下载中心集成

- “仅音频”及包含音频的下载模式提供“下载完成后自动转写”。
- 用户显式选择优先于全局默认；未显式选择时读取转写设置中的默认值。
- 无音频输出的“仅视频”任务不允许自动转写。

## 工作流与状态规则

### 转写主链路

1. 选择本地媒体或已完成下载任务。
2. 校验文件存在性和格式，读取媒体元信息。
3. 检查所选模型是否已安装且校验有效。
4. 创建转写任务并进入等待队列。
5. FFmpeg 抽取/重采样为 16kHz 单声道 16-bit PCM WAV。
6. 调度器在并发上限和下载优先级约束下分配槽位。
7. `whisper.cpp` 生成分段文本、语言和时间戳。
8. 后处理、保存规范化结果、生成目标格式并删除临时 PCM。
9. 发出完成/失败事件与系统通知。

### 进度事件

事件：`transcribe://progress`

| 字段 | 语义 |
| --- | --- |
| `task_id` | 转写任务 ID |
| `stage` | 预处理、加载模型、转写中、后处理、保存中 |
| `progress` | 0-100 |
| `processed_seconds` | 已处理音频秒数 |
| `total_seconds` | 总音频秒数 |
| `speed` | 相对实时速度，例如 1.8x |
| `eta` | 剩余秒数 |
| `message` | 当前阶段说明 |

模型下载事件：`transcribe://model_download_progress`，至少包含模型 ID、已下载字节、总字节、百分比和状态。

### 缓存与命名

- 同一文件、模型、语言、输出格式的转写结果默认复用缓存。
- “重新转写”绕过缓存。
- 输出名为 `{源文件名}.{语言}.{扩展名}`；冲突追加 `(1)`、`(2)`。
- 临时 PCM 在完成、失败或取消后均需清理。

### 资源调度

- 转写并发默认 1，可配置 1-3。
- 下载与转写可并行，但转写优先级低于下载。
- 长音频分段处理并在静音附近对齐边界，避免一次性占用过多内存。

## 技术与分发约束

- ASR 引擎：`whisper.cpp` sidecar；服务层通过 `Transcriber` trait 隔离。
- 音频预处理：现有 FFmpeg sidecar，输出 16kHz 单声道 PCM WAV。
- 模型管理：文件系统持有模型文件，现有设置持久化机制保存目录、默认值和下载源。
- 模型完整性：下载后校验 SHA-256；模型清单必须固定下载地址、预期字节数和摘要。
- `tauri.conf.json` 的 `bundle.externalBin` 增加 whisper sidecar。
- sidecar 随主程序更新，模型保留在用户数据目录。
- Windows/macOS/Linux 使用目标三元组命名；本地环境只承担 Windows 真实烟测。

## 非功能约束

- Tiny/Base 在 4 核 CPU 目标为不低于 2x 实时，Small 不低于 1x 实时；必须在可复现硬件上记录测量，不能由单元测试代替。
- GPU 模式支持自动/开启/关闭，并按 sidecar 实际构建能力降级或报出可理解错误。
- 新文案同时提供简体中文与英文。
- 页面和任务交互保持键盘可达、焦点可见、状态非仅颜色表达。
- 不实现实时录音、说话人分离、字幕翻译或完整时间轴编辑器。

## 上游开放问题

1. PRD 规定 SHA-256，但官方模型说明主要公布其他摘要格式；实现需维护经下载验证的应用模型清单，不能把不同摘要算法混用。
2. “标点恢复”没有指定独立算法；默认以 Whisper 输出标点为准，不新增网络或额外模型，开关仅控制允许的本地后处理。
3. “优先使用平台字幕”依赖 B 站 CC 字幕接口细节；主语义明确，可通过 `SubtitleProvider` adapter 承接，接口字段变化不得阻塞本地 ASR 主链路。
4. GPU 能力由实际 sidecar 构建决定；设置为“开启”但二进制不支持时不得静默假装已启用。
