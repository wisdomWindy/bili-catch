# 启动更新确认流程

## 模块标识

`startup-update-flow`

## 模块名称

启动更新确认流程

## 来源快照

“添加应用启动时自动检查新版本并弹出确认更新弹窗。”用户确认：点击“立即更新”后直接下载安装，完成后自动重启应用。批准设计还明确：设置开启时检查一次；最新版或检查失败静默；发现新版显示当前与目标版本；提供稍后和立即更新；安装期间不可关闭；失败可重试；手动更新保持不变。

## Markdown 规范化快照

- 触发：设置加载成功且 `autoCheckUpdates=true`。
- 检查次数：每次应用根生命周期一次。
- 静默分支：latest、检查异常、设置关闭或加载失败。
- 弹窗：当前版本、新版本、“稍后”、“立即更新”。
- 安装：确认后下载并安装，完成后自动重启。
- Pending：禁止关闭弹窗和重复提交。
- Error：本地化错误、保留弹窗、允许重试。
- 回归边界：设置页手动检查与托盘检查保持不变。

## 业务意图

让启用自动更新检查的用户在任意启动页面及时获知新版，同时把安装决定留给用户。

## 用户可见范围

仅新增全局更新确认弹窗及其安装中、失败状态；无新页面和导航入口。

## 表单、表格、展示与交互

- 不新增表单或表格。
- 展示标题、说明、当前版本、目标版本和错误区域。
- 稍后关闭，立即更新提交，失败后立即更新按钮可重试。

## 工作流与状态规则

`idle -> checking -> hidden(latest/error)` 或 `idle -> checking -> available -> installing -> relaunch/error`。`error -> installing` 支持重试；`available -> dismissed` 本次运行不再自动提示。

## 依赖与受影响邻居

- 依赖设置 store ready 状态和值。
- 依赖 `ReleaseActionsPort`。
- 邻接设置页手动更新与托盘更新事件。

## Page Design 路由决定

需要。模态框的内容层级、按钮、焦点、锁定与响应式约束必须先固定。

## 下游 Spec 义务

完整保留触发闩锁、静默分支、版本字段、安装锁定、错误重试、自动重启和邻接回归要求。
