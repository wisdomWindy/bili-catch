# 页面设计：启动更新确认

## 交付单元标识

`startup-update-flow`

## 页面目标

在不改变用户当前页面和任务上下文的前提下，清晰告知新版本并取得安装确认。

## 目标用户与场景

启用了自动检查更新、启动 BiliCatch 且远端存在更高版本的桌面用户。

## 布局结构

- 全局居中模态层，覆盖当前路由内容但不触发导航。
- 固定为紧凑型内容容器，桌面最大宽度约 420px，移动端保留 16px 视口边距。
- 内容从上到下为图标、标题、说明、版本对照、错误区和操作区。

## 视觉层级

1. 更新图标与“发现新版本”标题。
2. 一句说明安装后会自动重启。
3. 当前版本与新版本并列或两行对照，新版本使用品牌色强调。
4. 错误信息仅在安装失败时出现，使用危险色但不改变弹窗宽度。
5. 底部右对齐操作：“稍后”为次要操作，“立即更新”为品牌色主操作。

## 区块拆分

- Header：图标与标题。
- Summary：安装结果说明。
- Version comparison：两个带标签的版本值。
- Error feedback：`role=alert` 的本地化错误。
- Actions：安全退出和确认安装。

## 样式方向

- 复用现有表面色、边框、阴影、6-8px 圆角和按钮规范。
- 不嵌套卡片，不增加渐变、装饰插画或过大标题。
- 使用 Lucide `Download` / `RefreshCw` 或等价既有图标；安装中使用稳定尺寸的 loading 图标。
- 版本值使用等宽数字字体，文本不使用负字距或随视口缩放字号。

## 交互骨架

- 打开时默认聚焦“稍后”，关闭后恢复原焦点。
- 非安装态：Escape、遮罩和“稍后”均可关闭。
- 安装态：关闭、遮罩、Escape 和重复点击均禁用；按钮文案变为“正在安装”，图标旋转但按钮尺寸不变。
- 安装失败：弹窗保持打开，错误区出现，“立即更新”恢复并承担重试。
- Tab 在两个可用操作间循环，避免焦点逃出模态。

## 响应式行为

- 宽度使用 `min(420px, calc(100vw - 32px))`。
- 窄屏版本对照改为单列，按钮可保持横排；文案允许自然换行。
- 最小按钮高度 36px，长英文文案不会溢出。

## 设计风险

- 全局弹窗必须位于 Naive UI provider 内，否则主题与焦点行为不一致。
- 安装 Promise 通常因重启不返回；pending 状态不能依赖成功后的本地复位。
- 错误区出现时应避免按钮垂直跳动过大。

## 未决 UI 问题

无。
